# churnmap ロードマップ

git 履歴からモジュール / ファイル / 関数の変更頻度（churn）を集計し、
ターミナルにヒートマップとして表示するツール。**実装はすべて自分で書く**（Rust 学習が目的）。

方針（決定済み）:

- git の呼び出しは `std::process::Command` で `git` CLI を叩く（git2 クレートは使わない）
- Step 5 まででいったん「使えるツール」として完成させ、関数レベル（Step 6）は別リリース

---

## Step 1: 生データ取得 — 目安 30 分

`git log --numstat` の出力を `String` で受け取り、標準出力にそのままダンプする。

- 使うもの: `std::process::Command`（`.arg()` / `.output()`）、`String::from_utf8`
- フォーマット指定は `--format=%H%x09%ad` のように 1 引数で渡す（シェル経由ではないのでクォート不要）
- 対象リポジトリのパスはひとまずハードコードで OK（引数化は Step 5 のついでに）
- エラー処理は `.expect()` で雑に。`Result` / `?` への置き換えは Step 3 後のリファクタ課題にとっておく

**完了条件:** `cargo run` で my-own-apps 自身の git log がターミナルに流れる。

## Step 2: パーサー — 一番の学びどころ

Step 1 の出力を `Vec<Commit>` に変換する。

- 設計する struct: `Commit`（ハッシュ・日付・`Vec<FileChange>`）、`FileChange`（追加行・削除行・パス）
- 慣れる操作: `lines()`, `split_whitespace()`, `parse::<u32>()`, パターンマッチ
- **予告済みの罠:**
  - リネーム行: `old => new` / `dir/{old => new}/file` 表記
  - バイナリファイル: 追加/削除行数が `-` になる
- テストを 1 本書く（固定の log 文字列を入力にして、コミット数と変更ファイル数を assert）。
  後のリファクタで必ず効いてくる

**完了条件:** コミット総数とファイル変更の総数が `git log --numstat | grep -c ...` 等での手動確認と一致する。

## Step 3: ファイル別集計 — 最初のマイルストーン

`HashMap<PathBuf, ChurnStats>` でファイルごとに変更回数・追加/削除行数を集計する。

- 慣れる操作: `entry().or_insert_with()`, ソート（`Vec` に落として `sort_by`）
- ついで課題: `.expect()` を `Result` + `?` に置き換えるリファクタ

**完了条件:** 変更回数トップ 20 のランキングが `println!` で出る。ここで一度「動くツール」。

## Step 4: モジュール階層への畳み込み

パスをディレクトリ単位で集約する。`src/parser/mod.rs` の変更が `src/parser` と `src` にも積み上がる形。

- 設計判断（自分で選ぶ）: 再帰的なツリー構造 vs パス前方一致で HashMap のまま畳む
- **予告済みの罠:** 所有権とツリー構造の相性。HashMap ベースで逃げるのは正解のうち

**完了条件:** ディレクトリ指定で、その配下の合計 churn が出せる。

## Step 5: ターミナルヒートマップ

数値を色の濃淡にマップして、ツリー表示で一望できるようにする。

- 選択肢: ANSI エスケープを自分で書く / `colored` / `ratatui`（まず ANSI 手書きが学びは多い）
- 色スケール: 最大値で正規化 → 5 段階くらいのバケツで十分
- ついでに CLI 引数（対象リポジトリのパス、`--top N` など）。`std::env::args` で足りる

**完了条件:** `cargo run -- <repo path>` 一発で、色付きツリーが出る。ここで v0.1 としてリリース（タグを打つ）。

## Step 6（発展・別リリース）: 関数レベル

`git log -L` をファイル×関数で叩くと遅すぎるので、
diff のハンク行番号と現在の AST の関数範囲を突き合わせる方式を検討する。

- キーワード: `git log -p` のハンクヘッダ（`@@ -a,b +c,d @@`）、`tree-sitter` クレート
- 難易度が跳ねる。Step 5 の v0.1 を使い込んで、欲しくなってから着手する
