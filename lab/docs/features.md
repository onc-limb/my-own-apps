# 拡張マトリクス

> これは**機能一覧ではない**。
> 「この機能を作る」と決めたリストではなく、
> **「この技術を学びたくなったら、この題材ではこう足せる」という受け皿の一覧**である。

## なぜ機能一覧にしないのか

機能セットを先に決め打ちすると、後から学びたい技術が出てきたときに題材が受け止められない。
だから決めるのは「何を扱うドメインか」だけにして、
機能は**学びたい技術から逆算して後付けする**。

題材（技術書コレクション + 観測基盤）は、そのための**器**として選ばれている。
器の条件は次の 6 つで、この題材はすべてを満たす。

1. 時間とともにデータが溜まるか → キュー・バッチ・集計・時系列分析の受け皿
2. 複数人 / 複数デバイスが同時に触る理由があるか → WebSocket・権限
3. 一覧・詳細・フィルタ・編集の画面が要るか → 状態管理・ルーティング
4. 外からデータが入ってくるか → 取り込みパイプライン・並行処理・レート制限・Cron
5. 中に重い計算が 1 つあるか → Web Worker → WASM → ベンチ比較
6. 自分が使いたいか → 継続（これが一番効く）

## マトリクス

| 学びたい技術 | 足す機能 | どこで動くか | フェーズ |
| --- | --- | --- | --- |
| **DOM 操作・イベント** | テーマ切替、Lab の絞り込み | ブラウザ（素の JS） | 0 |
| **状態管理** | 本棚一覧のタグ・フィルタ・並び替え・無限スクロールを **素の JS / React / Signals の 3 実装** | フロント | 0 → 1 |
| **フォームと楽観更新** | 蔵書の登録・編集・読了マーク | フロント + `/api/ts` | 1 |
| **外部 API 連携** | ISBN から書誌・書影を取り込む | Worker | 1 |
| **RDB とスキーマ設計** | 蔵書・タグ・読了・監視対象 | D1 + Drizzle | 1 |
| **キュー / 非同期ジョブ** | `/collect` → Queue → 集計 consumer、書誌取り込み、監視プローブ投入 | Queues | 2 |
| **時系列データの集計** | 日次・時間別ロールアップ、カーディナリティ対策 | Worker + D1 | 2 |
| **チャート描画** | ダッシュボードのグラフ（まず SVG を手で、後でライブラリと比較） | フロント | 2 |
| **Node.js の本領** | 取り込みジョブを Node streams + `worker_threads` で書く | Container（Node） | 3 |
| **同一コードのランタイム比較** | 同じ Hono アプリを Worker 版と Node 版で動かし、応答時間を自作解析で比べる | Worker と Container | 3 |
| **コンテナ運用** | Dockerfile、イメージサイズ、コールドスタート計測 | Containers | 3 |
| **並行処理・レート制限** | 監視対象を並列プローブ、書誌 API のドメイン別レート制限とリトライ | Node のセマフォ → Rust の tokio と比較 | 4 |
| **WebSocket** | ダッシュボードの「今の訪問者」ライブ表示、障害通知プッシュ | **Durable Object 版と Container の `ws` 自作版の 2 実装** | 4 |
| **ストリーミング（SSE）** | 取り込みログの逐次表示 | Container（Node） | 4 |
| **Cron / スケジューラ** | 監視プローブの定期実行、日次ロールアップ、書誌の再取得 | Cron Trigger → Container | 4 |
| **キャッシュ戦略** | 集計結果の KV、書影の Cache API、`stale-while-revalidate` | Worker | 4 |
| **Rust（ブラウザ WASM）** | 書影からの色抽出・リサイズ | ブラウザ WASM | 5 |
| **Rust（サーバ）** | `/api/rs/*` を axum で。TS 版・Node 版と 3 つ並べる | Container | 5 |
| **全文検索** | 蔵書の目次・感想の検索、ログ検索のクエリ言語を自作 | D1 FTS5 → Rust（tantivy）と比較 | 5 |
| **型の言語間共有** | Rust struct → TS 型（`ts-rs` / `typeshare`）か OpenAPI か | `packages/` | 5 |
| **Python とデータ分析** | 読書傾向、監視データの異常検知、コホート分析 | Container（pandas / DuckDB が R2 の Parquet を読む） | 6 |
| **オブジェクトストレージ** | 生イベントの NDJSON / Parquet、書影の保存 | R2 | 6 |
| **認証・権限** | 管理画面は自分専用、蔵書は公開共有リンク | Worker | 未定 |
| **可観測性** | 自作解析で自分のサイトの実装比較を実測する | ドッグフーディング | 常時 |

## 埋まっていない行を足すときのルール

新しく学びたい技術が出てきたら、この表に行を足す。そのとき次を満たすか確認する。

- ✅ **題材の中で自然な機能になっているか**（「WebSocket を使うために意味のない機能を足す」になっていないか）
- ✅ 既存の層に載るか（新しいドメインを増やしていないか）
- ✅ URL 名前空間の予約表と矛盾しないか（→ `architecture.md`）
- ❌ 既存の機能を作り直すだけになっていないか
