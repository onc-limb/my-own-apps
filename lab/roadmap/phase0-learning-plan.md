### なぜ到達判定を自己説明にしているのか

Bisra ら (2018) は 64 の研究・69 の効果量を対象にしたメタ分析で、
**自己説明（self-explanation）を促すと学習成果が向上する**ことを示した
（ランダム効果モデルで g = 0.55）。
また Roediger & Karpicke (2006) は、読み返すより**思い出そうとするほうが長期保持に効く**
ことを示している。

→ だからこのドキュメントは「読んで理解する資料」ではなく
**「作った後に自分へ問い直すための質問集」** として作られている。
コードが動いた時点で終わりにしない。

## §2 学習テーマ

### L1. ゼロから Web ページを立ち上げる順番

**ねらい**: 白紙の `index.html` から始めるとき、次に何をすべきかで迷わないこと。
個々の技術ではなく、**手順そのもの**を身体に入れる。

順番は 4 段。**各段で「まだやらないこと」を守るのが本質。**

| 段 | やること | この段で**まだやらないこと** | なぜこの順番か |
| --- | --- | --- | --- |
| 0 | このページが何かを 1 文で書く | マークアップ | 内容が決まらないと構造も決まらない |
| 1 | **メタデータの定義** — `<!DOCTYPE html>` / `<html lang>` / `charset` / viewport / `title` / `description` / OG / favicon / `color-scheme` | 中身 | 文字化けとモバイル表示は後から気づきにくい。`charset` は**先頭 1024 バイト以内**という制約がある |
| 2 | **セクション立て** — ランドマーク、見出し階層、本文をテキストだけで置く | **CSS を 1 行も書かない** | **CSS 無しで読めるかが、構造が正しいかの試験になる**。ここでアウトラインが破綻していたら、見た目を整えても支援技術には伝わらない |
| 3 | **スタイルを当てる** — トークン定義 → 基本タイポと下地 → レイアウト → 状態 | JS | 個別に色を書き始めると後で統一できない。ボックスの役割が決まらないと Grid か Flex かも選べない |
| 4 | **振る舞いを足す（JS）** | — | HTML / CSS で成立しているものの上に乗せる。JS が失敗しても読める状態を保つ |

**ゴール**: この 4 段を説明でき、実際に**段を飛ばさずに**1 枚を組み上げられる。

**到達判定**

1. なぜ CSS を書く前に「CSS 無しで読めること」を確認するのか
2. `charset` を `<head>` の先頭付近に置く理由は何か
3. トークンの定義を、個別の色指定より先にやる理由は何か
4. 段 2 の途中で「見た目が寂しいから CSS を書きたい」と思ったとき、なぜ我慢するのか

**細目**: H1 H2 H3 / C1

### L2. 要素を「意味」で選ぶ

**ねらい**: 見た目ではなく**役割**で要素を選べるようになること。
ここを外すと、後から CSS や JS でいくら足しても直らない。

学ぶ内容:

- ランドマーク要素（`header` / `nav` / `main` / `footer` / `section`）と `div` の違い
- 見出し階層は見た目の大きさと独立していること
- **リンクとボタンの選び分け**（遷移するか、その場で何かするか）
- リストのマークアップと、装飾で意味を壊さない書き方
- ラベルと入力の結び付け（`label` / `for` / `id`）
- HTML だけで足りる場面（`<details>` など）を先に探す癖

**ゴール**: 要素を選んだ理由を毎回言える。**キーボードだけでページを一周できる。**

**到達判定**

5. `section` と `div` の違いを、支援技術の観点で説明できるか
6. なぜ `h1` は 1 つなのか。見た目の大きさと見出しレベルはどういう関係か
7. リンクとボタンの選び分けの基準を、1 文で言えるか
8. `label` と `placeholder` の役割の違いは何か
9. Tab キーだけで操作して、どこで詰まったか。どう直したか

**細目**: H2 H3 H4 H5 H6 H7 H8 / C10 / P4

### L3. デザイントークンとカスケード設計

**ねらい**: 色や余白を **1 箇所で変えられる**状態にすること。
そして `!important` を使わずに済む CSS の組み方を知ること。

学ぶ内容:

- `:root` のカスタムプロパティでトークン化（色・余白・角丸・タイポ・影）
- **カスタムプロパティが継承すること**。これが L5 のダークモードの土台になる
- カスケード・詳細度・継承の関係
- ボックスモデルと `box-sizing`
- 論理プロパティ（`padding-block` / `margin-inline`）
- ファイル分割と、**読み込み順がカスケード順になること**

**ゴール**: トークンを 1 つ変えるとサイト全体が変わる。詳細度で困っていない。

**到達判定**

10. カスタムプロパティは継承するか。それがダークモードにどう効くか
11. `!important` を書きたくなったとき、何が起きているサインか
12. CSS ファイルを分けた基準は何か。読み込み順を入れ替えると何が起きるか

**細目**: C1 C2 C3 C4 C12

### L4. レイアウトを CSS で組む

**ねらい**: メディアクエリを最小限にして、画面幅に自然に追従させること。

学ぶ内容:

- Flexbox（1 次元）— ヘッダーの配置、絞り込みバー、バッジの並び
- Grid（2 次元）— カードグリッド `repeat(auto-fit, minmax(...))`
- `auto-fit` と `auto-fill` の違い
- 流動的なサイズ指定 — `clamp()` で見出し、`ch` で本文の行長
- メディアクエリを**使わずに**解ける範囲を先に探す

**ゴール**: カードの列数が幅に応じて変わり、横スクロールが出ない。
それをメディアクエリ 1 個以下で実現できている。

**到達判定**

13. Flexbox と Grid をどう選び分けたか
14. `auto-fit` と `auto-fill` は何が違うか。どちらを選んだか、なぜか
15. `clamp()` を使うとメディアクエリが減るのはなぜか

**細目**: C5 C6 C7

### L5. ライトモードとダークモードの切り替え

**ねらい**: テーマ切替を **3 段構え**として設計できること。
そして **CSS でどこまで完成させ、JS には何だけを任せるか**の線を引けること。

| 段 | 何をするか | 担当 |
| --- | --- | --- |
| 1 | `color-scheme` でブラウザ既定の UI（スクロールバー、フォーム部品）を揃える | CSS |
| 2 | `prefers-color-scheme` で **OS 設定に追従**させる | CSS |
| 3 | `[data-theme]` でユーザーの**明示的な選択で上書き**する | CSS の定義 + JS の切替 |

学ぶ内容:

- 上の 3 段の役割分担。**JS が無くても段 2 まで完成していること**
- 優先順位の仕様を先に決める（明示的な選択 > OS 設定 > 既定）
- トグルの永続化（`localStorage`）と、保存に失敗しても壊れない書き方
- **FOUC（一瞬デフォルトのテーマが見える現象）** — スクリプトの実行タイミングとの関係
- 両テーマでのコントラスト。ダークで彩度の高い色は眩しい
- `prefers-reduced-motion` で切替アニメーションを無効化する

**ゴール**: JS を無効にしても OS 設定に追従する。
トグルで上書きでき、リロードしても保たれ、**切替時にちらつかない**。

**到達判定**

16. OS がダークで、前回ユーザーが light を選んでいたら、どちらを優先すべきか。その根拠は
17. `color-scheme` は何を変えるのか。`prefers-color-scheme` との違いは
18. テーマ適用を遅延スクリプトでやると何が起きるか。なぜそうなるのか
19. `localStorage` が例外を投げるのはどんなときか。落ちない書き方にしたか
20. トグルの状態を、支援技術にはどう伝えているか

**細目**: C2 C8 C9 C11 / J1 J4 J5

### L7. 状態が増えたときの管理（Phase 0 の山）

**ねらい**: **状態が複数になると何が壊れるか**を体験すること。
題材は Lab の絞り込み（検索文字列 / 選択タグ / 並び順の 3 個）。

反映先は 5 箇所ある。

- カードの表示・非表示
- 「該当 N 件」の件数
- タグチップ自身の選択状態
- 0 件のときの空状態メッセージ
- URL（`URLSearchParams`）

学ぶ内容:

- イベント委譲（要素が動的に増える想定だと必要になる）
- 配列の絞り込みと並べ替え（`filter` / `sort` / `localeCompare`）
- 入力の間引き（デバウンスを自分で書く）
- URL に状態を載せる（`pushState` と `replaceState` の選択）
- **同じ機能を 2 通りで書いて比べる**
  - (a) イベントごとに関係する DOM を直接いじる
  - (b) 単一の `state` オブジェクトを持ち、`render()` で全部を描き直す

**ゴール**: **面倒さを言語化できること。** 動くことよりこちらが目的。

> ここで感じる面倒さは失敗ではなく **Phase 0 の成果**である。
> Phase 1 で React を入れるとこれが消える。そのとき
> 「React は状態から DOM を導出する道具だ」という理解が、
> 抽象的な説明ではなく**自分が味わった痛みの解消**として入る。
> 根拠は [../docs/concept.md](../docs/concept.md)（A Time for Telling）。

**到達判定**（※ 24 と 25 が Phase 0 全体の中心）

24. **状態を 1 つ増やしたとき、直さないといけない場所をどうやって列挙したか**
25. **`state → render()` にまとめると何が楽になり、何が犠牲になるか**
26. 絞り込み UI で `pushState` と `replaceState` のどちらを選んだか。なぜか
27. イベント委譲が必要になるのはどんなときか
28. `sort` を呼ぶ前に気をつけることは何か
29. デバウンスは何を防いでいるのか

**24 と 25 の答えは `journal/` に文章で残す。**
それが Phase 1 で React を入れたときの**比較の基準線**になる。

**細目**: J3 J6 J7 J8 J9

## §4 細目 — HTML

| # | 学ぶこと | 担うページ要素 | つまずきやすい点 |
| --- | --- | --- | --- |
| **H1** | 文書の骨格とメタ情報（`<!DOCTYPE html>`、`lang`、`charset`、viewport、`title`、`description`、OG） | `<head>` 全体 | `lang` を書き忘れると読み上げ言語が狂う。viewport が無いとモバイルで縮小表示される |
| **H2** | ランドマーク要素（`header` / `nav` / `main` / `footer` / `section`） | ページ全体の骨格 | `div` との違いは「支援技術に役割が伝わるか」。`section` は**アクセシブルな名前がないとランドマークにならない** |
| **H3** | 見出しの階層 | `h1` 1 つ + 各 section の `h2` + カードの `h3` | 見た目の大きさで選ばない。レベルを飛ばさない |
| **H4** | リンクとボタンの区別 | カードのリンク / テーマトグル / タグチップ | **遷移するなら `a`、その場で何かするなら `button`**。`div` に click を付けるとキーボードで押せない |
| **H5** | リストのマークアップ | カードグリッド（`ul > li > article`） | `list-style: none` を当てると支援技術からリストの意味が消える実装がある。対処法を調べる |
| **H6** | フォーム部品とラベル | 検索 `input`、並び順 `select`、タグの `input[type=checkbox]` | `label` と `for` / `id` の結び付け。**プレースホルダはラベルの代わりにならない** |
| **H7** | 画像と代替テキスト | ロゴ、（任意で）カードのサムネイル | 装飾画像は `alt=""`。`width` / `height` を書かないとレイアウトシフトが起きる |
| **H8** | ネイティブ要素で済ませる判断 | `<details>` を補足説明に | JS を書く前に「HTML だけで足りないか」を毎回問う癖をつける |

## §5 細目 — CSS

| # | 学ぶこと | 担うページ要素 | つまずきやすい点 |
| --- | --- | --- | --- |
| **C1** | カスケード・詳細度・継承 | 全体 | `!important` を使いたくなったら、それは詳細度の設計が失敗したという合図 |
| **C2** | カスタムプロパティでトークン化 | `:root` の色・余白・角丸・タイポ | 変数は**継承する**。だから `[data-theme]` で再定義すると配下に伝播する。**これがダークモードの仕組みそのもの** |
| **C3** | ボックスモデルと `box-sizing` | カードとボタンの余白 | `border-box` を全体に当てる定番の理由を、自分で説明できるか |
| **C4** | 論理プロパティ | 余白全般（`padding-block` / `margin-inline`） | `left` / `right` ではなく `inline-start` / `end` で書く意味 |
| **C5** | Flexbox（1 次元） | ヘッダーの配置、絞り込みバー、バッジの並び | 隙間は `gap` で作る。`margin` で作らない |
| **C6** | Grid（2 次元） | カードグリッド `repeat(auto-fit, minmax(...))` | `auto-fit` と `auto-fill` の違い。カードが 1 枚のときの挙動 |
| **C7** | 流動的なサイズ指定 | `clamp()` で見出し、`ch` で本文の行長 | メディアクエリを書く前に `clamp()` と `minmax()` で解けないかを考える |
| **C8** | テーマの 3 段重ね | `color-scheme` / `prefers-color-scheme` / `[data-theme]` | **CSS だけで OS 追従までを完成させ、JS には「上書き」だけを任せる**という役割分担 |
| **C9** | 色とコントラスト | 本文、バッジ、フォーカスリング | ダークモードで彩度の高い色は眩しい。両テーマで基準を満たすか |
| **C10** | 状態のスタイル | `:hover` / `:focus-visible` / `[aria-pressed]` / `:has()` | `:focus` ではなく `:focus-visible`。フォーカスリングを消さない |
| **C11** | モーションの配慮 | トグルと表示切替の transition | `prefers-reduced-motion: reduce` で無効化する |
| **C12** | ファイル分割 | `tokens.css` / `base.css` / `layout.css` | **読み込み順がカスケード順**になる。分割の基準を自分で決める |

## §6 細目 — JavaScript

| # | 学ぶこと | 担うページ要素 | つまずきやすい点 |
| --- | --- | --- | --- |
| **J1** | スクリプトの読み込みと実行順序 | `<script type="module">` と `<head>` の短いインラインスクリプト | `defer` と `module` は既定で遅延する。**テーマ適用だけは遅延させられない（FOUC）** |
| **J2** | 要素の取得と `dataset` | カードの `data-tags` / `data-status` | `querySelectorAll` が返すのは配列ではない。`Array.from` が要る場面 |
| **J3** | イベントとイベント委譲 | タグチップの束 | チップごとに listener を付けるか、親に 1 つ付けるか。**要素が動的に増える想定だと委譲が要る** |
| **J4** | 属性とクラスの操作 | `hidden` / `classList` / `aria-pressed` / `aria-live` | 見た目だけ変えて `aria-*` の更新を忘れる。`hidden` と `display: none` の関係 |
| **J5** | `localStorage` と例外処理 | テーマの永続化 | プライベートモードや設定で**例外を投げる**。保存できるのは文字列だけ |
| **J6** | URL に状態を載せる | 絞り込み条件 | `pushState` と `replaceState` の違い。入力のたびに履歴を積むと戻るボタンが壊れる |
| **J7** | **単一の state と render 関数** | 絞り込み全体 | **L7 の山。** 直接 DOM をいじる書き方と `state → render()` の書き方を**両方書いて比べる** |
| **J8** | 配列の絞り込みと並べ替え | `filter` / `sort` / `localeCompare` | `sort` は破壊的。日本語の並び順をどう決めるか |
| **J9** | 入力の間引き | 検索ボックス | デバウンスを自分で書く（`setTimeout` / `clearTimeout`） |
| **J10** | モジュール分割 | `theme.js` / `filter.js` | **ビルド無しで `import` が動く条件**（`type="module"`、相対パス、拡張子必須、オリジン） |

## §7 細目 — 公開と検証

| # | 学ぶこと | 担うもの | つまずきやすい点 |
