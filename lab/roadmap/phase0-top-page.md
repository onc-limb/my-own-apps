# Phase 0 — トップページ 1 枚とデプロイ

> **ゴール**: 素の HTML / CSS / JS で書いたトップページ 1 枚を、`lab.onc-limb.com` で公開する。
> 機能は最小でよい。ただし **デプロイの形だけは、後から変えにくいので先に正しく決める**。
>
> **何を学ぶか・どの要素で学ぶか**は [phase0-learning-plan.md](phase0-learning-plan.md) に分けてある。
> こちらはスコープと手順を扱う。

---

## 1. 先に確定させること（不可逆の判断）

機能は後から足せるが、この 5 つは後から変えると痛い。理由は
[../docs/architecture.md](../docs/architecture.md) の表を参照。

| # | 判断 | Phase 0 での結論 |
| --- | --- | --- |
| 1 | ホスティング | Workers + Static Assets（Pages は使わない） |
| 2 | ドメイン | **`lab.onc-limb.com` を最初から繋ぐ**。`*.workers.dev` で運用を始めない |
| 3 | URL 名前空間 | 予約表で全パスを先に確定（今使うのは `/` と `/assets/*` だけ） |
| 4 | リポジトリ構成 | `apps/web/public/` に直置き。`apps/` の階層を最初から切る |
| 5 | Worker の形 | **`main` なしの assets-only Worker で始める**。後で `main` を足すだけで Worker コードを追加できる（URL は変わらない） |

### URL の形に関する追加の判断

`assets.html_handling` は末尾スラッシュの扱いを決める設定で、
**後から変えると URL が変わる**（= リンクと計測データの継続性が壊れる）。
デフォルトは `auto-trailing-slash`。Phase 0 で決めて以後触らない。

## 2. ページの構成案

トップページは **Lab インデックス**。Phase 0 の時点で Lab はまだ 1 つも無いので、
「構想中」のカードを並べる。それ自体がロードマップの可視化になり、
このサイトが何をする場所なのかを一目で伝える。

```
┌───────────────────────────────────────────────┐
│ [skip link]  ← 視覚的には隠す                    │
├───────────────────────────────────────────────┤
│ <header>                                       │
│   lab                       [ テーマ切替 ]  ← JS 段階 1
│   一行の説明                                    │
├───────────────────────────────────────────────┤
│ <main>                                         │
│  ┌ <section> このサイトは何か ──────────────┐   │
│  │  3〜4 行。学習目的であることを明記         │   │
│  └───────────────────────────────────────┘   │
│                                                │
│  ┌ <section> Lab 一覧 ────────────────────┐   │
│  │  [検索____] [#react][#rust][#ws]  [並び順▾] │  ← JS 段階 2
│  │  該当 N 件                                │   │
│  │  ┌────────┐ ┌────────┐ ┌────────┐  │   │
│  │  │ タイトル │ │        │ │        │  │   │
│  │  │ 説明     │ │        │ │        │  │   │
│  │  │ ○構想中  │ │ ●公開  │ │        │  │   │
│  │  │ #vanilla │ │ #react │ │        │  │   │
│  │  └────────┘ └────────┘ └────────┘  │   │
│  └───────────────────────────────────────┘   │
│                                                │
│  ┌ <section> 今使っている技術 ──────────────┐   │
│  └───────────────────────────────────────┘   │
├───────────────────────────────────────────────┤
│ <footer>  GitHub / 最終更新                     │
└───────────────────────────────────────────────┘
```

### 要素と、それによって学べること

| 要素 | 学べること |
| --- | --- |
| `header` / `main` / `section` / `footer`、skip link | セマンティック HTML、文書アウトライン、アクセシビリティの基礎 |
| `h1` は 1 つ、以下を階層で | 見出しレベルとアウトラインの関係 |
| Lab カードを `ul > li` で組む | 意味のマークアップと装飾の分離 |
| カードのグリッド | **CSS Grid の `repeat(auto-fit, minmax(...))`** — メディアクエリ無しでレスポンシブになる |
| `:root` にカスタムプロパティ | デザイントークン、変数のカスケード。**Phase 1 の React 版でもそのまま使える資産になる** |
| ダークモード | `prefers-color-scheme` と `[data-theme]` の併用、詳細度、属性セレクタ |
| `:focus-visible`、タブ順 | キーボード操作とフォーカス可視化 |
| `<details>` を FAQ などに | JS を書かずにできることの範囲を知る |
| `<title>` / OG タグ / favicon | 公開に必要な最低限のメタ情報 |
| `prefers-reduced-motion` | アニメーションの配慮 |
| CSS / JS を外部ファイルに分ける | リクエスト数とキャッシュ（Phase 2 の計測の伏線） |

## 3. JS の段階設計（Phase 0 の核心）

素の JS を 1 つの塊としてやらない。**意図的に 2 段階に分ける。**

### 段階 1 — テーマ切替

状態は **1 個**（light / dark）。反映先も **1 箇所**（`<html>` の属性）。

学べること:

- `addEventListener`、`dataset`、属性の読み書き
- `localStorage` による永続化
- **初期化の順序の問題（FOUC）** — ページ描画後に JS でテーマを当てると、
  一瞬デフォルトのテーマが見える。これをどう防ぐかが最初の設計課題になる
- OS 設定（`prefers-color-scheme`）とユーザーの明示的な選択の優先順位

素の JS で**快適に書ける**規模。ここは気持ちよく終わる。

### 段階 2 — Lab の絞り込み

状態は **3 個**（検索文字列 / 選択中のタグ集合 / 並び順）。
反映先が **複数**になる。

- カードの表示・非表示
- 「該当 N 件」の件数表示
- タグチップ自身の選択状態
- 0 件のときの空状態メッセージ
- URL（`URLSearchParams` に載せる）

学べること:

- `data-*` 属性、`classList`、`hidden`、イベント委譲
- 状態を URL に持たせる（共有可能なフィルタ）
- **そして本題**: 状態を 1 つ変えたら、**関係する DOM を全部手で直さないといけない**。
  状態が 1 つ増えるたびに直す場所が増えていく（組み合わせが増える）

### この「破綻」を体験することが目的

段階 2 で感じる面倒さは、**失敗ではなく Phase 0 の成果**である。

Phase 1 で React を入れると、この面倒さが消える。
そのとき「React は状態から DOM を導出してくれる道具だ」という理解が、
抽象的な説明ではなく**自分が味わった痛みの解消**として入る。

これは学習科学の "A Time for Telling" そのもの
（→ [../docs/concept.md](../docs/concept.md)）。
**先に問題の次元に気づいてから解決策を教わると、新しい問題への応用が効く。**

だから Phase 0 で「面倒だからフレームワークを入れる」のは、
遠回りの回避ではなく **学習機会の破棄**にあたる。

## 4. 意図的に入れておく伏線

今は不要だが、入れておくと後がスムーズになるもの。

| 伏線 | 何のため |
| --- | --- |
| カードの情報を `data-*` 属性に持たせる | Phase 1 で D1 から配信しても DOM の構造が変わらない |
| 絞り込み状態を `URLSearchParams` に載せる | 共有リンク、将来のサーバサイドレンダリング |
| デザイントークンを CSS の別ファイルに切り出す | Phase 1 の React 版と共有する |
| 計測スクリプトの差し込み位置を 1 箇所決めておく | Phase 2 の `/collect` を足すときに迷わない |
| カードに「ステータス」と「技術バッジ」を最初から持たせる | このサイトの性格（実装を比較する場）が一目で伝わる |

## 5. まだ使わないもの

Phase 0 では次を**使わない**。理由は「便利さを味わう前に、それが何を解決しているのかを知る」ため。

- ❌ フレームワーク / ライブラリ（React、Vue、Alpine、jQuery、CSS フレームワーク）
- ❌ ビルドツール（Vite、esbuild、バンドラ、トランスパイラ）
- ❌ TypeScript
- ❌ CSS プリプロセッサ
- ❌ D1、KV、Queues、Durable Objects、Containers
- ⚠️ 例外: **wrangler**（デプロイ CLI）。これはフロントエンドのビルドではないので使う

## 6. 作業の順序

1 つずつコミットする。各ステップで「何が学べたか」を意識する。

| # | やること | 到達点 |
| --- | --- | --- |
| 1 | `index.html` の骨格だけ書く（CSS も JS も無し） | ブラウザで開くと、装飾なしでも読める文書になっている |
| 2 | Cloudflare にデプロイして `lab.onc-limb.com` で見えるようにする | **ここで公開の形が確定する**。以後は中身を足すだけ |
| 3 | デザイントークン（`:root` のカスタムプロパティ）を定義 | 色と余白が変数で管理されている |
| 4 | レイアウトを CSS Grid で組む | 画面幅を変えるとカードの列数が変わる |
| 5 | ダークモードを CSS だけで実装（OS 設定に追従） | JS 無しで OS のテーマに従う |
| 6 | **JS 段階 1**: テーマ切替トグル | リロードしても選択が保たれ、FOUC が起きない |
| 7 | **JS 段階 2**: 検索 + タグ絞り込み + 並び替え | URL を共有すると同じ絞り込み状態で開く |
| 8 | アクセシビリティとメタ情報の仕上げ | 下のチェックリストが全部通る |

**ステップ 2 を早い段階に置いているのは意図的。**
「完成してからデプロイ」ではなく「骨格だけの状態で先にデプロイ」する。
デプロイの形は後から変えにくいので、最初に確定させて安心してから中身を作る。

## 7. デプロイ手順の骨格

> 設定ファイルの中身は自分で書く。ここでは**必要な項目と、それが何を決めるのか**だけを示す。

### 7.1 wrangler の用意

`package.json` を作らず `npx wrangler@latest ...` で使う手もあるが、
**バージョンを固定したほうが後で困らない**ので、
`devDependencies` に `wrangler` だけを入れた最小の `package.json` を置くのがよい。
これはフロントエンドのビルドではないので Phase 0 の制約に反しない。

### 7.2 `wrangler.jsonc` に必要な項目

| キー | 何を決めるか | Phase 0 での方針 |
| --- | --- | --- |
| `name` | Worker 名。`*.workers.dev` のサブドメインにもなる | 後から変えると workers.dev の URL が変わる。独自ドメインを使うので影響は小さいが、最初に決める |
| `compatibility_date` | ランタイムの挙動を固定する日付 | 作成日にする。むやみに動かさない |
| `assets.directory` | 静的ファイルの置き場所 | `./apps/web/public` |
| `assets.html_handling` | 末尾スラッシュの扱い | デフォルト（`auto-trailing-slash`）。**後から変えると URL が変わる** |
| `assets.not_found_handling` | マッチしないリクエストの扱い | 後で `404.html` を作るなら `404-page`。今は省略でもよい（404 が返る） |
| `main` | Worker のエントリポイント | **書かない**。assets-only Worker として始める |
| `routes` | 独自ドメインの割り当て | `[{ "pattern": "lab.onc-limb.com", "custom_domain": true }]` |

`main` は assets-only Worker では**省略できる**。
Worker コードが必要になった Phase 1 以降で `main` を足せば、URL は変わらない。

### 7.3 コマンドの流れ

```
wrangler login          # 認証（既に Paid プランのアカウントを選ぶ）
wrangler deploy         # ビルドなし。public/ の中身がそのまま上がる
```

`lab.onc-limb.com` は `routes` に書いてデプロイするか、
ダッシュボードの Worker 設定から割り当てる。
**`onc-limb.com` ゾーンが Cloudflare の DNS で管理されている必要がある。**

### 7.4 確認すること

- `lab.onc-limb.com` で HTTPS で開ける（`*.workers.dev` ではなく）
- CSS と JS が `/assets/...` から読み込めている
- 存在しないパスを叩いたときの挙動を把握している

## 8. 詰まりそうなポイント（答えは書かない）

自分で解くこと。どこを見ればよいかだけ記す。

1. **テーマ切替でページが一瞬白く光る** — スクリプトが走るタイミングと、
   ブラウザが CSS を適用するタイミングの順序を考える。`<head>` に何を置けるか
2. **OS がダークなのに、前回 light を選んでいたらどちらを優先すべきか** —
   仕様として先に決める。「明示的な選択 > OS 設定 > デフォルト」で矛盾がないか
3. **絞り込みで「該当 0 件」のときに何も表示されない** —
   状態の数だけ画面の分岐があることに気づく。ここが段階 2 の学びの中心
4. **タグを複数選んだときの挙動** — AND か OR か。仕様を決めずに書くと破綻する
5. **`URLSearchParams` と `history`** — 絞り込みのたびに履歴を積むか、置き換えるか
6. **キーボードだけで全部操作できるか** — Tab で回して確認する
7. **JS を切っても内容が読めるか** — カードは HTML にあるので読めるはず。
   絞り込みだけが効かない状態が正しい（プログレッシブエンハンスメント）

## 10. Phase 1 への引き継ぎ

Phase 0 が終わったら、次のことを言語化して `journal/` に残す。
それが Phase 1 で React を入れたときの**比較の基準線**になる。

- 段階 2 で、状態を 1 つ足すたびに何箇所直したか

- 初回表示までの体感速度（Phase 2 で数字にする）
