# 機能仕様: stretch-card

## 変更履歴

- 2026-08-18 初版作成

## 概要と提供価値

gacha-draw が抽選で確定した `StretchItem` 1 件を、**部位・レア度・種目名・実施時間・手順・種目固有の注意** が 1 画面で読み切れる密度のカードとして描画する機能。ご褒美カード（`kind == .reward`）も分岐なしで同じレイアウトに乗せる。

gacha-draw が暫定で置いた `PlaceholderResultView` を置き換えるのが第一の役割で、加えて図鑑（stretch-collection）の入手済み種目詳細でも同じビューを再利用できるよう、スタイル 2 種（`.result` / `.detail`）とフッタースロットを持つ。

提供価値は 2 つ。

1. **出たものをその場で理解できる**: レア度・部位を色と文字の両方で示し、番号付き手順と実施時間を同一画面に置く。ガチャ結果から「読む → 身体を動かす」までに画面遷移を挟まない。L1 最優先の学習容易性（初回起動 60 秒以内に実施開始）の後半 20 秒を担う。
2. **時間予算を 1 ミリ秒も増やさない**: カードは `StretchItem` の純粋な関数として描画され、独自の入場アニメーション・非同期処理・I/O を一切持たない。gacha-draw が確保済みの「コールドスタート → 結果表示 3.0 秒」予算に **0 秒**を追加する。

カードは状態を持たない。永続化もネットワークもなく、`StretchItem` を渡せば同じ絵が出る。これにより表示ロジックの検証が純粋関数のユニットテストだけで完結する。

## スコープ（やること / やらないこと）

### やること

- 表示用派生モデル `StretchCardContent` と、`StretchItem` から組み立てる純粋関数 `make(from:)`
- カード本体ビュー `StretchCardView`（レア度バッジ / 部位チップ / 絵文字 / 種目名 / 実施時間 / 番号付き手順 / 注意）
- スタイル 2 種: `.result`（ガチャ結果用）/ `.detail`（図鑑詳細用）のメトリクス定義
- フッタースロット（`@ViewBuilder`）。stretch-timer の「はじめる」・gacha-draw の「もう 1 回」を呼び出し側から差し込める形にする
- レア度 → 色・ラベルの対応 `RarityStyle`（ライト / ダーク両対応、アセット追加なし）
- 秒数 → 表示文字列 `DurationLabel`（`60` → 「1 分」等）
- 手順エリアのみをスクロール可能にし、ヘッダとフッターを常時可視に保つレイアウト
- `PlaceholderResultView` の削除と `GachaView` の結果表示箇所の差し替え
- Dynamic Type / VoiceOver / 色覚多様性 / ダークモードへの対応
- 上記すべてのユニットテスト（派生値・境界値・防御的処理・性能）

### やらないこと

- **抽選ロジック・演出**（gacha-draw の責務）。カードは確定済みの `StretchItem` を受け取るだけ
- **種目データの保持・検証**（stretch-catalog が唯一の正。カードは読むだけ・検証しない）
- **タイマーの起動と実行**（stretch-timer）。フッターにボタンの「置き場所」を用意するところまで
- **実施記録・図鑑登録・入手済みバッジ**（practice-record）。「登録済み」等の状態表示をカードに持たせない
- **図鑑画面そのもの・未入手のシルエット表現**（stretch-collection）。カタログ仕様どおり「伏せる判断」は図鑑側の責務
- 画像・イラスト・図解アセット（視覚補助は `StretchItem.emoji` の 1 文字のみ）
- カード自身の入場・退場アニメーション（gacha-draw のクロスフェード区間に乗せる。§4.6 参照）
- カードのシェア・スクリーンショット出力・テキストコピー・お気に入り登録
- カードのカスタマイズ設定（文字サイズ設定画面・配色テーマ切り替え）。OS の Dynamic Type / 外観設定への追随のみ行う
- 多言語化（日本語直書き。`Localizable.strings` を作らない）
- 手順テキストのリッチ表現（Markdown 解釈・リンク検出・部分強調）
- サーバー・外部 API・アナリティクス送信（L1 制約）

## 機能仕様の詳細

### 1. 責務境界

| 相手 | 方向 | 受け渡すもの |
|---|---|---|
| stretch-catalog | 受け取る | `StretchItem`（`name` / `kind` / `bodyPart` / `rarity` / `durationSeconds` / `emoji` / `steps` / `caution`）と `BodyPart.displayName` / `Rarity.displayName` |
| gacha-draw | 受け取る | `GachaPhase.revealed(StretchItem)` の `StretchItem` 1 件 |
| gacha-draw | 渡す | `RarityStyle.accent(for:)`（SR/UR 演出の色味変化が参照する単一の正） |
| stretch-timer | 渡す | フッタースロット。カードは timer を import しない |
| stretch-collection | 渡す | `StretchCardView(item:style: .detail)`。未入手のシルエット表現は図鑑側 |
| practice-record | 参照しない | 入手済み判定はカードの関心事ではない |

依存の向きは **stretch-card → stretch-catalog の一方向のみ**。stretch-card から gacha-draw / timer / record / collection を参照しない。

### 2. 表示用派生モデル

`StretchItem` をそのままビューに配ると、防御的処理と整形が `body` 内に散る。表示に必要な形へ 1 回で変換する純粋関数を挟み、テストをここに集約する。

```swift
// StretchCardContent.swift
struct StretchCardContent: Equatable {
    let rarity: Rarity          // バッジの色・ラベルの決定に使う
    let rarityLabel: String     // "N" / "R" / "SR" / "UR"
    let bodyPartLabel: String   // "首" / "肩" / ... （BodyPart.displayName をそのまま）
    let name: String
    let emoji: String           // 必ず 1 文字（先頭 1 文字に切り詰め済み）
    let durationText: String?   // "60秒" 相当。nil なら時間チップを描かない
    let steps: [String]         // 空配列なら手順セクションごと描かない
    let caution: String?        // trim 後に空なら nil

    static func make(from item: StretchItem) -> StretchCardContent
}
```

**`make(from:)` の変換規則（すべて防御的処理を含む）**

| 入力 | 規則 |
|---|---|
| `rarity` | `Rarity.displayName` をそのまま `rarityLabel` に採用 |
| `bodyPart` | `BodyPart.displayName` をそのまま採用。`kind` による分岐をしない（ご褒美カードも同じ経路） |
| `name` | そのまま。空文字でも例外にせず空のまま描く（レイアウトは崩れない） |
| `emoji` | `String(item.emoji.prefix(1))`。2 文字以上なら先頭 1 文字、空なら空文字（絵文字行の高さは確保したまま何も描かない） |
| `durationSeconds` | `1...` なら `DurationLabel.text(seconds:)` の結果、`0` 以下なら `nil` |
| `steps` | 各要素を `trimmingCharacters(in: .whitespacesAndNewlines)` し、空要素を除去した配列 |
| `caution` | trim 後に空なら `nil`、非空ならその文字列 |

カタログのバリデータが上記の異常値をすべて弾く前提だが、**カード側でクラッシュしないことを二重に保証する**（L1 妥協特性「運用性」により、実行時のエラー表示・リカバリ UI は持たない。壊れたデータでも「静かに欠けたカード」が出るだけにする）。

### 3. 秒数の表示規則

```swift
// DurationLabel.swift
enum DurationLabel {
    static func text(seconds: Int) -> String
}
```

| 条件 | 出力 | 例 |
|---|---|---|
| `seconds < 60` | `"\(seconds)秒"` | 20 → 「20秒」 / 45 → 「45秒」 / 59 → 「59秒」 |
| `seconds % 60 == 0` | `"\(分)分"` | 60 → 「1分」 |
| それ以外 | `"\(分)分\(秒)秒"` | 75 → 「1分15秒」 / 90 → 「1分30秒」 |

カタログ規約の値域は 20〜90 秒（初回同梱の最大値 60）。上記 3 分岐で 20〜90 の全域を隙間なく覆う。`DateComponentsFormatter` は使わない（ロケール依存の出力揺れを避け、テストを厳密値でアサートできるようにするため）。

### 4. 画面仕様

#### 4.1 配置とスタイル

`StretchCardView` は画面ではなく **部品**。ガチャ画面の結果表示領域、図鑑の詳細シートのいずれにも同じビューが入る。L1 の「画面はガチャ・図鑑・履歴の 3 つまで」に画面を追加しない。

```swift
// StretchCardView.swift
struct StretchCardView<Footer: View>: View {
    let item: StretchItem
    var style: StretchCardStyle = .result
    @ViewBuilder var footer: () -> Footer
}

extension StretchCardView where Footer == EmptyView {
    init(item: StretchItem, style: StretchCardStyle = .result)
}
```

| スタイル | 用途 | 絵文字サイズ | 種目名 | 枠線 |
|---|---|---|---|---|
| `.result` | ガチャ結果 | 56pt | `.title2` bold（22pt） | 1.5pt |
| `.detail` | 図鑑の入手済み詳細 | 40pt | `.title3` bold（20pt） | 1.0pt |

差分はメトリクスのみで、要素構成・順序・防御的処理は共通。

#### 4.2 カード内の要素（上から順）

| # | 要素 | 内容 |
|---|---|---|
| 1 | ヘッダ行 | 左: レア度バッジ（塗り + 文字）／右: 部位チップ（枠線 + 文字）。`HStack` + `Spacer` |
| 2 | 絵文字 | 中央寄せ。`StretchCardContent.emoji` の 1 文字 |
| 3 | 種目名 | 中央寄せ。最大 2 行、`.minimumScaleFactor(0.8)`、3 行目以降は末尾省略 |
| 4 | 実施時間 | 中央寄せ。「⏱ 60秒」。`durationText == nil` なら行ごと非表示 |
| 5 | 区切り線 | 1pt。`Color(.separator)` |
| 6 | 手順 | 番号付きリスト。`ScrollView` 内。**この領域だけがスクロールする** |
| 7 | 注意 | `caution != nil` のときだけ。「⚠️」+ テキスト、`.caption`、角丸 8pt の淡色背景。手順の下・スクロール領域内 |

見出しラベル（「手順」「注意」等）は置かない。番号と ⚠️ で役割が伝わるため、ラベルを増やさない方針を gacha-draw と揃える（学習容易性 1 位）。

#### 4.3 レイアウトメトリクス（設計基準: iPhone SE 第 2/3 世代 375×667・縦画面固定）

画面幅 375pt、セーフエリア高 647pt（ステータスバー 20pt を除く）で予算を組む。これより大きい端末では手順エリアが広がるだけで構成は変わらない。

**画面（`.result` 使用時のガチャ結果画面）の縦配分**

| 区間 | 高さ |
|---|---|
| 画面上余白 | 16 |
| カード | 最大 543 |
| カード〜フッター間 | 16 |
| フッターボタン | 56 |
| 画面下余白 | 16 |
| 合計 | **647** |

検算: 16 + 543 + 16 + 56 + 16 = **647** ✓（セーフエリア高と一致）

**カード内の固定部（`.result`・種目名 2 行の最悪ケース）**

| 要素 | 高さ |
|---|---|
| カード上下パディング（20 × 2） | 40 |
| ヘッダ行 | 24 |
| 余白 | 12 |
| 絵文字（56pt フォント） | 68 |
| 余白 | 8 |
| 種目名（22pt × 最大 2 行、行高 29） | 58 |
| 余白 | 6 |
| 実施時間（15pt、行高 20） | 20 |
| 余白 | 14 |
| 区切り線 | 1 |
| 余白 | 14 |
| 固定部 合計 | **265** |

検算: 40+24+12+68+8+58+6+20+14+1+14 = **265** ✓
→ 手順スクロール領域 = 543 − 265 = **278pt**（種目名が 1 行なら固定部 236pt、手順領域 307pt）

**手順テキストの折り返し**

- カード幅 = 375 − 20×2（画面左右余白）= 335
- テキスト幅 = 335 − 20×2（カード内パディング）− 24（番号）− 8（番号との間隔）= **263pt**
- 本文 17pt（全角 1 文字 ≈ 17pt）→ 1 行あたり **約 15 文字**
- 手順 n 件・各 k 行のときの高さ = `24 × n × k + 10 × (n − 1)`（行高 24、手順間 10）

| ケース | 高さ | 278pt に対して |
|---|---|---|
| 4 手順 × 1 行（初回同梱の典型。例: `neck-02`） | 24×4 + 10×3 = **126** | 収まる |
| 4 手順 × 2 行 | 24×8 + 10×3 = **222** | 収まる |
| 6 手順 × 1 行 | 24×6 + 10×5 = **194** | 収まる |
| 6 手順 × 2 行 | 24×12 + 10×5 = **338** | スクロール |
| 6 手順 × 4 行（カタログ規約の最大: 6 件 × 60 文字） | 24×24 + 10×5 = **626** | スクロール |

規約上の最大ケースでも**ヘッダ（レア度・部位・名称・時間）とフッターは常時可視のまま**、手順だけがスクロールで全文に到達できる。カードごと縦スクロールさせない理由は、「レア度と実施時間が視界から消えない」ことが 1 画面で読み切れる密度の要件だから。

スクロール可否のヒントは **OS 標準のスクロールインジケータのみ**。フェードマスク・矢印・「▾ もっと見る」などの追加装飾を持たない（保守性 3 位: 装飾のための条件分岐を作らない）。

#### 4.4 配色

アセットカタログを一切追加しない。`UIColor { traitCollection in ... }` を包む `AdaptiveColor.make(light:dark:)` ヘルパで、ライト / ダークの 2 色から `Color` を作る。

```swift
// RarityStyle.swift
enum RarityStyle {
    static func accent(for rarity: Rarity) -> Color        // バッジ塗り・枠線の色
    static func badgeForeground(for rarity: Rarity) -> Color // バッジ文字色
}
```

| レア度 | accent（ライト） | accent（ダーク） |
|---|---|---|
| N | `#6E6E73` | `#98989D` |
| R | `#2A62C4` | `#6FA8FF` |
| SR | `#7B4FD1` | `#B69BFF` |
| UR | `#8C6000` | `#F0C14B` |

- バッジ: 塗り = accent 100%、文字色 = ライト `#FFFFFF` / ダーク `#1C1C1E`
- カード枠線: accent の不透明度 50%
- カード背景: `Color(.secondarySystemBackground)`。SR / UR のみ accent 8% を重ねる
- 画面背景: `Color(.systemBackground)`
- 部位チップ: 枠線 `Color(.separator)`、文字 `Color(.secondaryLabel)`（レア度色を使わない＝色の意味を 1 つに保つ）
- 影は使わない。段差の表現は枠線と背景色差だけで行う

**コントラスト**: バッジの文字色と塗り色の輝度コントラスト比は、ライト / ダーク × 4 レア度の全 8 組で **4.5:1 以上**（WCAG AA）。設計上の最小はライトの N でおよそ 5.1 で、閾値に対して余裕がある。テストは WCAG の相対輝度式で実測し **4.5 以上**をアサートする（設計値そのものを厳密にアサートしない）。

**色覚多様性**: レア度は必ずバッジ内に文字（`N` / `R` / `SR` / `UR`）を併記する。色のみでレア度を伝える箇所を作らない。

#### 4.5 タイポグラフィと Dynamic Type

| 要素 | フォント | 追随 |
|---|---|---|
| レア度バッジ / 部位チップ | `.caption` bold（13pt） | 上限 `.xxxLarge` |
| 種目名 | `.title2` bold（22pt） | 上限 `.xxxLarge` |
| 実施時間 | `.subheadline`（15pt） | 上限 `.xxxLarge` |
| 手順本文 | `.body`（17pt） | **上限なし（AX5 まで追随）** |
| 注意 | `.caption`（13pt） | 上限なし |

ヘッダ側に上限を置くのは、固定部が伸びて手順領域が消えるのを防ぐため。手順と注意はスクロール領域内にあるため上限を設けず、アクセシビリティサイズでも全文が読める。

#### 4.6 アニメーション

**`StretchCardView` は独自のアニメーションを一切持たない。** `.animation` 修飾子・`withAnimation`・`Task.sleep`・`transaction` をビュー内に書かない。

理由は時間予算。gacha-draw は「タップ → 結果カード表示」に最大 1.81 秒（抽選 0.01 + 演出 1.80）、コールドスタートからの合計 2.81 秒を割り当て、3.0 秒に対する余裕は 190ms しかない。カードが独自に 0.25 秒の入場アニメーションを足すと合計 3.06 秒となり予算を超える。したがってカードの出現は **gacha-draw の演出最終区間（クロスフェード 0.10 秒 / Reduce Motion 時 0.30 秒）に乗せる**。カード側は `transition(.opacity)` を宣言するだけで、駆動は gacha-draw が行う。

この制約により、Reduce Motion への追随もカード側では不要になる（gacha-draw 側の短縮演出がそのまま効く）。

#### 4.7 アクセシビリティ（VoiceOver）

読み上げ順序と粒度を固定する。

1. ヘッダ + 名称 + 時間を `accessibilityElement(children: .combine)` で 1 要素にまとめ、「レア度 N、首、首の横倒し、60秒」の順に読む
2. 絵文字は装飾のため `.accessibilityHidden(true)`
3. 手順は 1 行 1 要素。ラベルは「手順 1、背すじを伸ばして座る」
4. 注意は「注意、痛みが出たら中止する」
5. フッター（呼び出し側のボタン）

カード内にタップ可能要素を置かない（フッターのボタンのみが操作対象で、最小タップ領域 44×44pt はフッター側の責務）。

### 5. データモデル（永続化）

**なし。** 本機能は SwiftData のモデルを 1 つも定義せず、`ModelContext` を参照せず、`SwiftData` を import しない。カードは `StretchItem` の純粋な関数であり、スクロール位置以外の状態を持たない（スクロール位置は SwiftUI の `ScrollView` が管理し、画面破棄で消えてよい）。

### 6. 処理フロー

```
[gacha-draw: phase = .revealed(item)]
      ▼
GachaView の結果表示領域
      └─ StretchCardView(item: item, style: .result) {
             Button("もう1回") { viewModel.spin() }     ← フッタースロット（gacha-draw が渡す）
         }
      ▼
StretchCardView.body
      ├─ StretchCardContent.make(from: item)   ← 同期・純粋関数・目標 200µs 未満
      │      ├─ emoji を 1 文字に切り詰め
      │      ├─ DurationLabel.text(seconds:)
      │      ├─ steps を trim して空要素を除去
      │      └─ caution を trim（空なら nil）
      ├─ RarityStyle.accent(for:) / badgeForeground(for:)
      └─ ヘッダ / 絵文字 / 名称 / 時間 / 区切り線 / 手順(ScrollView) / 注意 / フッター を描画
      ▼
[表示完了]  ← I/O なし・非同期なし・追加待機なし
```

`make(from:)` は `body` が評価されるたびに呼ばれる。26 件規模で数十マイクロ秒の処理であり、キャッシュ層・`@State` への保持・`Equatable` による再計算抑制を **入れない**（L1 妥協特性「スケーラビリティ」）。

将来 stretch-timer が実装されたときは、フッターに `Button("はじめる")` が入るだけで、`StretchCardView` 側は 1 行も変わらない。

## 非機能要件

| 項目 | 値 | 根拠・備考 |
|---|---|---|
| gacha-draw の時間予算への追加 | **0 秒** | カードは独自アニメーション・非同期処理を持たない（§4.6）。コールドスタート → 結果表示 3.0 秒は gacha-draw 側の条件が引き続き支配的 |
| カード初回描画（レイアウト + テキスト描画） | 実機設計目標 **16.7ms 以内**（1 フレーム） | 画像デコード・I/O・非同期が無いため達成可能 |
| 　同上・テストのアサート閾値 | `StretchCardContent.make(from:)` **10,000 回が 2 秒以内**（1 回 200µs 相当の上限） | 描画時間は環境差で揺れるため、純粋関数の計算量を余裕を持った上限で代替検証する |
| SwiftData クエリ本数 | **0 本**（`SwiftData` を import しない） | カードは永続化層に触れない |
| ディスク読み書き回数 | **0 回** | |
| ネットワークリクエスト数 | **0 件** | L1 制約: サーバー・外部 API 禁止 |

## 非機能優先順位との対応

### 1 位: 学習容易性（説明書なしで初回起動 60 秒以内に最初のガチャ → 実施開始）

- **1 画面に情報を閉じる**: 部位・レア度・名称・実施時間・手順を 1 枚のカードに収め、「詳細を見る」「手順を開く」といった二次的な操作を作らない。ユーザーが覚える操作は 0。
- **ラベルを増やさない**: 「手順」「注意」といった見出しを置かず、番号と ⚠️ で役割を伝える。画面上の文字数を減らすことがそのまま読了時間の短縮になる。gacha-draw の「ボタンは『回す』の 2 文字のみ」と同じ方針。
- **60 秒の内訳を守る**: gacha-draw の設計では「結果カードの読了 約 20 秒」が割り当てられている。手順は 2〜6 行・各行 15 文字前後で折り返るため、実データ（4 手順・126pt）は視線移動なしで読める。カード側で読了時間を伸ばす要素（長文の免責、確率表記、統計表示）を一切足さない。
- **色に頼らない**: レア度はバッジの文字を必ず併記し、部位はレア度色を使わない中立色にする。「色の意味を 1 つに保つ」ことで説明が要らなくなる。
- **失敗状態を作らない**: エラー表示・「データがありません」プレースホルダ・リトライ導線を持たない。異常値は §2 の規則で静かに欠けるだけにする。

### 2 位: パフォーマンス（コールドスタート → 結果 3 秒以内、演出 60fps）

- **時間予算に 0 秒しか足さない**（§4.6）。カード独自の入場アニメーションを持てば 2.81 秒 + 0.25 秒 = 3.06 秒となり予算を超えるため、gacha-draw のクロスフェード区間に乗せる設計を固定点とする。
- **描画経路から I/O と非同期を排除**: `SwiftData` / `URLSession` / `Task` / `async` をカードのソースに持ち込まない。`body` の評価は同期の文字列処理のみ。
- **重いレンダリング機能を使わない**: `blur` / `shadow` / `mask` / `TimelineView` / `Canvas` を使わない。装飾は塗り・枠線・角丸だけで構成する。画像アセットを持たないためデコードも発生しない。
- **フォント計測を増やさない**: 種目名の `minimumScaleFactor` は 0.8 の 1 段のみ、他要素では使わない。多段の縮小はレイアウトパスの反復を招く。
- 手順の `ScrollView` は 6 要素以下の `LazyVStack` ではなく通常の `VStack` で構成する（要素数が高々 6 件で、遅延生成のオーバーヘッドの方が大きい）。

### 3 位: 保守性（週末開発でも壊さず拡張できる）

- **表示ロジックを純粋関数に隔離する**: `StretchCardContent.make(from:)` / `DurationLabel.text(seconds:)` / `RarityStyle` は SwiftUI の描画に依存しない。受け入れ条件のほぼ全項目が、UI テスト基盤なしのユニットテストで検証できる。
- **数値を 1 箇所に集約する**: 余白・角丸・フォントサイズ・枠線幅は `CardMetrics` と `StretchCardStyle` にまとめ、ビューにマジックナンバーを書かない。
- **レア度の色を単一の正にする**: `RarityStyle` をカード・gacha-draw の演出色の共通参照点にする。レア度の色を 2 箇所で定義しない。
- **種目追加でコードを触らせない**: 件数・部位名・レア度名をカード側にハードコードせず、すべて `StretchItem` と enum の `displayName` から取る。種目を 1 件足しても `Card/` 配下は 0 ファイル変更で動くことをテストで実証する。
- **テストは範囲・上限でアサートする**: コントラスト比は「4.5 以上」、性能は「10,000 回 2 秒以内」という余裕を持った境界で書く。「コントラスト比がちょうど 5.14」「描画が 12ms」のような、環境や実装の微修正で揺れる厳密値はアサートしない。一方、`DurationLabel` の出力文字列のように経路差で揺れない値は厳密にアサートする。
- **分岐を作らない**: ご褒美カード（`kind == .reward`）専用のレイアウト分岐を持たない。UR かつ `bodyPart == .rest` であることがカタログのバリデータで保証済みなので、レア度と部位の一般ルールだけで正しく描ける。

### 妥協特性で簡略化すること

| 妥協特性 | 本機能で作らないもの |
|---|---|
| スケーラビリティ | `make(from:)` の結果をキャッシュしない。`@State` 保持・`EquatableView`・`id` による再計算抑制を入れず、`body` 評価のたびに素朴に再計算する。手順リストの仮想化（`LazyVStack`）もしない。カード枚数は常に 1 枚で、最適化する対象がそもそも存在しない |
| 互換性・相互運用性 | カードのテキストをコピー・共有・エクスポートする経路を持たない。多言語化せず日本語直書き。iPad レイアウト・横画面・Dynamic Island・ウィジェット向けの派生レイアウトを作らない |
| 運用性 | 描画時間の計測基盤、レイアウト崩れの検知、スナップショットテストの自動化、アナリティクス、`print` / `os_log` によるログを持たない。表示崩れは自分が使って気づいたら直す |

## セキュリティ

本機能は完全ローカル・読み取り専用の表示部品で、ネットワーク・永続化・ユーザー入力のいずれも扱わない。攻撃面は「`StretchItem` の内容をどう描画するか」に限定される。

### 認証・認可

- **不要（実装しない）**。アカウント・ログインを持たない単一端末・単一ユーザー構成（L1 のスコープ外事項）。カードに権限による出し分けは存在しない。
- **書き換え経路を作らない**: `StretchCardView` は `StretchItem` を `let` で受け取り、保持も変更もしない。`@Binding` / `@State` で種目データを持たず、カタログの値を書き戻す API を公開しない。

### 入力検証

- ユーザー入力を一切受け付けない。テキストフィールド・数値入力・URL スキーム / ユニバーサルリンクの受け口を持たない。
- **`StretchItem` を「信頼しない入力」として扱う**: §2 の変換規則で、空文字・空配列・2 文字以上の絵文字・0 以下の秒数・空白のみの注意をすべて無害化してから描画する。カタログのバリデータが本来弾く値だが、カード単体でもクラッシュ・レイアウト破綻を起こさない。
- **テキストを書式として解釈させない**: 手順・注意・種目名はすべて `Text(verbatim:)` で描画する。`Text(_ key: LocalizedStringKey)` を使うと、データ中の `**` や `%@`、ローカライズキーと同名の文字列が意図せず書式化・置換される。カタログは開発者が書く JSON だが、表示層で解釈を許さないことを構造的な固定点にする。
- **リンク・データ検出をしない**: 手順文中の数字や記号を電話番号・日付として自動リンク化しない。テキスト選択（`textSelection`）も有効化せず、カードからテキストが持ち出される経路を作らない。
- 手順の表示件数に上限を設けない代わりに、スクロール領域で吸収する。件数超過による無限ループ・メモリ膨張は構造上発生しない（`steps` は有限配列の 1 回走査）。

### データ保護

- **何も保存しない**: SwiftData・UserDefaults・ファイル・キーチェーンのいずれにも書き込まない。カードは表示のたびに `StretchItem` から組み立て直される。
- 個人情報・端末識別子・位置情報・利用統計を扱わない。App Privacy「データ収集なし」申告（appstore-release-prep）と矛盾しない状態を維持する。
- **ネットワークを使わない**: `URLSession` / `Network` / `CFNetwork` を import しない。App Transport Security 設定を緩めない。
- **ログ出力を残さない**: `Card/` 配下に `print` / `os_log` / `debugPrint` を書かない。表示内容を外部へ送らない。
- スクリーンショット・画面録画の制限は設けない（カードに秘匿情報が無いため）。

### 依存関係

- 外部ライブラリ 0。`SwiftUI` / `Foundation` / `UIKit`（`AdaptiveColor` の `UIColor(dynamicProvider:)` のみ）で完結する（L1 制約: 外部ライブラリ原則ゼロ）。

### コンテンツ安全性（法務制約の技術的担保）

- カード側で固定文言を追加しない。画面に出る日本語はすべて `StretchItem` 由来か、記号（番号・⏱・⚠️）のみ。医学的効能・専門家監修を示唆する文言をカードのコードに書かない。
- 全体向けの注意書き（「痛みが出たら中止する・無理をしない」）は safety-notice の責務であり、カードには重複して置かない。カードが表示するのは `StretchItem.caution`（種目固有の注意）だけ。
- 禁止語チェックは stretch-catalog のバリデータが担う。カード側で再実装しない（検査点を 2 箇所に分散させない）。

## 実装方針

### 使用技術

- Swift 5.9+ / SwiftUI（iOS 17 以上）
- `UIKit` は `UIColor(dynamicProvider:)`（ライト / ダーク色の生成）にのみ使用
- **SwiftData は使わない**（import しない）
- テストは XCTest（標準）

### 既存実装との整合

- **stretch-catalog（status: issued_local）**: `StretchItem` / `Rarity` / `BodyPart` / `ItemKind` をそのまま利用する。**カタログの Swift コードと JSON は変更しない**。カードは `displayName` を経由して部位名・レア度名を得るため、部位名の文字列リテラルをカード側に持たない。
- **gacha-draw（status: issued_local）**: 同機能が「差し替え位置をコメントで明示する」としている `PlaceholderResultView` をここで置き換える。触るのは `GachaView` の結果表示箇所と演出の色参照だけで、`GachaViewModel` / `GachaDrawer` / `GachaAnimation` の秒数 / `DailyDrawStore` には一切変更を加えない。gacha-draw が定義していた演出用のレア度色があれば削除し、`RarityStyle.accent(for:)` に寄せる（レア度色の定義を 1 箇所に保つため）。
- **stretch-timer（未着手）**: フッタースロットを用意するのみ。カードは timer の型を参照せず、`Button("はじめる")` はタイマー実装時に呼び出し側へ足す。カードのコードは変更不要になる。
- **practice-record（未着手）**: 入手済み状態をカードに表示しない。カードは ownership を知らない。
- **stretch-collection（未着手）**: `.detail` スタイルを提供するが、図鑑画面・シルエット表示・レイアウト（グリッド / セクション）は作らない。
- **safety-notice（未着手）**: 相互作用なし。全体注意書きはカードに載せない。
- Xcode プロジェクト（`stretch-gacha/`）は stretch-catalog / gacha-draw の実装時に作成済みの想定。

### 実装手順

1. **`AdaptiveColor.swift`**: `static func make(light: UInt32, dark: UInt32) -> Color` を実装（引数は `0xRRGGBB`）。`UIColor(dynamicProvider:)` で `userInterfaceStyle` を見て切り替える。RGB 成分を取り出す純粋関数もここに置き、テストからコントラスト比計算に使えるよう `internal` にする。
2. **`RarityStyle.swift`**: §4.4 の 8 色を定義し、`accent(for:)` / `badgeForeground(for:)` を実装。`switch rarity` を `Rarity` の全ケースで網羅する（`default` を書かない＝レア度追加時にコンパイルエラーで気づける）。
3. **`DurationLabel.swift`**: §3 の 3 分岐を実装。`DateComponentsFormatter` を使わない旨をコメントに残す。
4. **`StretchCardContent.swift`**: §2 の変換規則を実装。各防御的処理（絵文字の切り詰め、steps の trim / 空要素除去、caution の空判定、秒数 0 以下の扱い）をそれぞれ独立した式に分け、テストから個別に確認できる形にする。
5. **`CardMetrics.swift` / `StretchCardStyle.swift`**: §4.3 の数値を定数化。`.result` / `.detail` の差分（絵文字サイズ・名称フォント・枠線幅）のみをスタイル側に置き、共通値は `CardMetrics` に置く。
6. **`StretchCardView.swift`**: §4.2 の 7 要素を上から実装。手順部だけを `ScrollView` で包み、ヘッダとフッターは `VStack` の固定位置に置く。すべてのテキストを `Text(verbatim:)` で描く。`.animation` / `withAnimation` / `Task` を書かない。§4.7 のアクセシビリティ修飾を付ける。`Footer == EmptyView` の便利イニシャライザも用意する。
7. **`GachaView.swift` の差し替え**: `PlaceholderResultView(item:)` を `StretchCardView(item:style: .result) { Button("もう1回") { ... } }` に置換。演出中のレア度色参照を `RarityStyle.accent(for:)` に統一し、gacha-draw 側の重複定数があれば削除する。`PlaceholderResultView.swift` を削除する。
8. **`StretchCardTests.swift`**: 「受け入れ条件」の各項目に 1:1 対応するテストを実装。コントラスト比は WCAG の相対輝度式（`L = 0.2126R + 0.7152G + 0.0722B`、各成分は sRGB のガンマ逆変換後）をテスト内のヘルパで計算し、8 組すべてで 4.5 以上をアサートする。同梱カタログ 26 件を回して `make(from:)` がクラッシュしないことを確認する。
9. **拡張性の実証テスト**: stretch-catalog がテスト用に用意しているフィクスチャ JSON（26 件 + ダミー 1 件）を読み、追加種目に対して `make(from:)` が正しい派生値を返すことを確認する。`Card/` 配下を 1 行も変更していないことをこのテストで示す。
10. **仕上げ確認**: `Card/` 配下が `SwiftData` / `URLSession` / `Network` を import していないこと、`print` / `os_log` が無いこと、Assets.xcassets への追加が 0 件であること、ビルド警告 0 件であることを確認する。iPhone SE 実機 / シミュレータでライト・ダーク・Dynamic Type AX5 の 3 条件を目視確認する。
