# 機能仕様: stretch-collection

## 変更履歴

- 2026-08-18 初版作成

## 概要と提供価値

同梱カタログの全 26 件（ストレッチ 24 + ご褒美カード 2）を **部位ごとのセクション + 3 列グリッド**で一覧表示し、未入手の種目はレア度と部位だけを見せて絵文字をグレー化・種目名を「???」で伏せる図鑑画面。入手済みのセルをタップすると stretch-card の `.detail` をシートで提示し、手順・実施時間をいつでも見返せる。

practice-record が導入した `RootTabView` に **図鑑タブを 1 つ足す**ことで、L1 の 3 画面（ガチャ / 図鑑 / 履歴）が揃う。

提供価値は 2 つ。

1. **「埋めたくなる」動機を可視化する**: どの部位のどのレア度がまだ空いているかが一目で分かり、収集の狙いが定まる。中身（種目名・手順）は伏せたままなので、埋める手段がガチャを回すこと以外に無い状態を保つ。義務感ではなく収集欲が継続を駆動する（L1 の副次指標「図鑑が埋めたくなる動機として機能しているか」を直接支える）。
2. **入手済みの内容を取りに行ける**: 一度出た種目の手順を後から確認できる。ガチャを回さないと手順が読めない状態を解消し、図鑑を「見返す場所」として成立させる。

本機能は **何も永続化しない**。入手済み判定は practice-record のメモリ索引から集合を 1 回受け取り、表示用のセクション構造はカタログと集合だけを引数に取る純粋関数で組み立てる。SwiftData のクエリは 0 本で、L1 最優先 2 位のパフォーマンス予算（コールドスタート → 結果表示 3.0 秒）に **0 秒**を追加する。

## スコープ（やること / やらないこと）

### やること

- 図鑑画面 `CollectionView`（部位セクション + 3 列グリッド + 詳細シート提示）
- セル表示用の派生モデル `CollectionCellContent` と、入手済み / 未入手の表現を決める純粋関数
- セクション構造 `CollectionSection` と、その構築純粋関数 `CollectionSectionBuilder.build(items:ownedItemIDs:)`
- セル `CollectionCellView`（レア度バッジ / 絵文字 or シルエット / 種目名 or「???」）
- 詳細シート `CollectionDetailSheet`（`StretchCardView(item:style: .detail)` + 「閉じる」）
- 未入手セルのタップ応答（セル内のラベルを「???」→「未入手」に差し替える。q1 回答 (2)）
- レイアウト定数 `CollectionMetrics`（列数・余白・セル寸法）
- `RootTabView` への図鑑タブ追加（ガチャ / 図鑑 / 履歴の 3 タブ構成に到達させる）
- 入手集合の変化を確実に画面へ反映させる再構築（`onAppear` / `scenePhase == .active`）
- 上記すべてのユニットテスト（並び順・入手済み判定・防御的処理・不変条件・性能）

### やらないこと

- **コンプ率・達成率の表示**（collection-progress の責務。L1 で「MVP では図鑑のシルエット表示のみで進捗を示す」と確定済み）。セクション見出しにも「3/5」のような件数・分数を出さない
- **NEW バッジ / 既読フラグ**（q3 回答で MVP 不採用）。既読状態の永続化を一切増やさず、入手済み / 未入手の 2 状態だけを持つ
- **実施記録・図鑑登録の書き込み**（practice-record の責務）。本機能は入手済み集合を **読むだけ**で、記録を作らない・消さない
- **抽選ロジック・演出**（gacha-draw の責務）。`Gacha/` 配下を 1 ファイルも変更しない
- **図鑑からのタイマー起動**（q4 回答で維持。図鑑は閲覧のみ）。`Timer/` を import しない
- **カード内のレイアウト**（stretch-card の責務）。詳細シートは `.detail` をそのまま使い、図鑑専用のカード表示を作らない
- **種目データの保持・検証**（stretch-catalog が唯一の正。図鑑は読むだけ）
- **整理軸の切り替え UI**（レア度別セクションへの切り替えセグメント。q2 回答で不採用）、検索・フィルタ・並べ替え・部位のジャンプ導線
- お気に入り登録、メモ、実施回数のセル内表示、最終実施日の表示
- 未入手セルのヒント表示（「あと何回で出やすい」等の確率説明）、提供確率の開示 UI
- 図鑑の共有・スクリーンショット出力・エクスポート
- 画像・イラスト・シルエット専用アセット（視覚補助は `StretchItem.emoji` の 1 文字とその階調変換のみ）
- グリッドの入場アニメーション、セル出現の時間差演出、入手時の解放演出
- 多言語化（日本語直書き。`Localizable.strings` を作らない）
- サーバー・外部 API・アナリティクス送信（L1 制約）

## 機能仕様の詳細

### 1. 責務境界

| 相手 | 方向 | 受け渡すもの |
|---|---|---|
| stretch-catalog | 受け取る | `StretchCatalog.shared.allItems`（表示対象の全件・JSON 記載順）、`BodyPart.displayName` / `sortOrder`、`Rarity.displayName` / `sortOrder`、`totalCount` |
| practice-record | 受け取る | `PracticeStore.ownedItemIDs() -> Set<String>`（メモリ索引から返る。**fetch 0 本**） |
| stretch-card | 受け取る | `StretchCardView(item:style: .detail)` とフッタースロット、`RarityStyle.accent(for:)` / `badgeForeground(for:)` |
| gacha-draw | 参照しない | 図鑑から抽選しない。`Gacha/` の型を import しない |
| stretch-timer | 参照しない | 図鑑から実施しない（q4 回答）。`Timer/` の型を import しない |
| collection-progress | 渡す（将来） | `CollectionSection` の配列と `ownedItemIDs`。コンプ率のヘッダを 1 つ足せば載る形にするが、本機能では表示しない |
| safety-notice | 受け取る | 相互作用なし（注意書きはルート側に被さる。表示制御は safety-notice の責務） |

依存の向きは **stretch-collection → stretch-catalog / stretch-card / practice-record** の一方向。他機能から stretch-collection の型を参照させない。`PracticeStore` に触れるのは `CollectionView.swift` の 1 箇所だけで、純粋関数群は `Set<String>` と値型しか知らない。

### 2. 整理軸（q2 回答: 部位を外側、レア度を内側）

**セクション = 部位、セクション内 = レア度昇順**。切り替えセグメントは置かない（画面上の操作対象を増やさない）。

| 順 | セクション | 見出し文字列 | 件数（初回同梱） |
|---|---|---|---|
| 1 | 首 | `BodyPart.neck.displayName` | 5 |
| 2 | 肩 | `BodyPart.shoulder.displayName` | 5 |
| 3 | 腰 | `BodyPart.lowerBack.displayName` | 5 |
| 4 | 背中 | `BodyPart.upperBack.displayName` | 4 |
| 5 | 脚 | `BodyPart.legs.displayName` | 3 |
| 6 | 目・手首 | `BodyPart.eyesWrists.displayName` | 2 |
| 7 | ご褒美 | `BodyPart.rest.displayName` | 2 |

検算: 5 + 5 + 5 + 4 + 3 + 2 + 2 = **26** ＝ `catalog.totalCount` ✓

- セクションの順序は `BodyPart.sortOrder` 昇順。`rest` は `sortOrder` が末尾に定義されているため、ご褒美セクションが最後に来る（**本機能でソート順を再定義しない**）。
- ご褒美カードは通常の部位セクションと**同列**に置く。専用の枠線・背景・見出し装飾を作らない（分岐を増やさない方針を stretch-card から継承）。
- 見出し文字列は `BodyPart.displayName` をそのまま使う。**部位名の文字列リテラルを `Collection/` に置かない**。
- 件数が 0 件の部位が生じた場合、そのセクションごと描かない（カタログのバリデータが 6 部位への 1 件以上を保証するため通常は発生しない防御的処理）。
- 見出しはスクロールに追随させない（`pinnedViews` を使わない）。固定ヘッダのための条件分岐を作らない。

### 3. 未入手の見せ方（q1 回答: (a) + タップ (2)）

| 要素 | 入手済み | 未入手 |
|---|---|---|
| レア度バッジ | `RarityStyle` の色 + 文字（N/R/SR/UR） | **同じ**（色も文字もそのまま） |
| 部位 | セクション見出しで示す | **同じ**（伏せない） |
| 絵文字 | `StretchItem.emoji` の 1 文字をそのまま | 同じ 1 文字を `.grayscale(1.0).opacity(0.35)` で描く（シルエット） |
| 種目名 | `StretchItem.name` | **「???」** |
| 実施時間・手順・注意 | 詳細シートで見られる | **見せない**（シートを開かない） |
| セル背景 | `Color(.secondarySystemBackground)` | `Color(.tertiarySystemFill)` |
| セル枠線 | `RarityStyle.accent(for:)` の不透明度 50%・1.0pt | `Color(.separator)`・1.0pt |
| 種目名の文字色 | `Color(.label)` | `Color(.secondaryLabel)` |

**「どの部位のどのレア度が空いているか」は分かり、「何が出るか」は分からない**状態を作る。狙いを定めさせつつ、埋める手段をガチャに限定する。

**未入手セルのタップ（q1 回答 (2)）**

- タップしたセルの種目名ラベルが **「???」→「未入手」** に差し替わる。絵文字はシルエットのまま、シート・ダイアログ・トーストは出さない。
- 状態は `@State private var revealedUnownedID: String?` の 1 つだけで持つ。**同時に「未入手」と出るセルは常に 1 つ**。同じセルを再タップすると「???」に戻り、別の未入手セルをタップすると表示がそちらへ移る。
- タイマー・非同期・アニメーションを使わない（即時差し替え）。この状態は永続化せず、タブを離れれば消えてよい。
- VoiceOver では表示状態にかかわらず常に「未入手」と読む（§5.5）。視覚上のトグルは読み上げに影響しない。

### 4. 表示用派生モデル

`StretchItem` をそのままセルに配ると、伏せる判断と整形がビューに散る。表示に必要な形へ 1 回で変換する純粋関数に集約する。

```swift
// CollectionCellContent.swift
struct CollectionCellContent: Equatable, Identifiable {
    let id: String              // StretchItem.id
    let isOwned: Bool
    let rarity: Rarity          // バッジの色に使う
    let rarityLabel: String     // "N" / "R" / "SR" / "UR"
    let emoji: String           // 必ず 1 文字（先頭 1 文字に切り詰め済み。未入手でも同じ値）
    let displayName: String     // 入手済み: item.name / 未入手: "???"
    let accessibilityLabel: String

    static func make(from item: StretchItem, isOwned: Bool) -> CollectionCellContent
}

// CollectionSection.swift
struct CollectionSection: Equatable, Identifiable {
    let id: String              // BodyPart.rawValue
    let title: String           // BodyPart.displayName
    let cells: [CollectionCellContent]
}
```

**`make(from:isOwned:)` の変換規則（防御的処理を含む）**

| 入力 | 規則 |
|---|---|
| `emoji` | `String(item.emoji.prefix(1))`。2 文字以上なら先頭 1 文字、空なら空文字（セルの絵文字行の高さは確保したまま何も描かない） |
| `name`（入手済み） | そのまま。空文字でも例外にせず空のまま描く |
| `name`（未入手） | 常に `"???"`（`item.name` を参照しない＝派生モデルに実名が入らない構造にする） |
| `rarity` | `Rarity.displayName` をそのまま `rarityLabel` に採用 |
| `accessibilityLabel` | 入手済み: `"\(name)、レア度 \(rarityLabel)、入手済み"` / 未入手: `"未入手、レア度 \(rarityLabel)"` |

未入手セルの派生モデルに `item.name` / `steps` / `durationSeconds` を**そもそも載せない**ことで、伏せ漏れが構造的に起きない状態にする。

```swift
// CollectionSectionBuilder.swift — 副作用なしの純粋関数
enum CollectionSectionBuilder {
    /// items: カタログの全件（JSON 記載順）
    /// ownedItemIDs: practice-record 由来の入手済み ID 集合
    static func build(items: [StretchItem],
                      ownedItemIDs: Set<String>) -> [CollectionSection]
}
```

**構築規則（この順で適用する）**

1. `items` を **記載順のまま**走査し、`bodyPart` でグループ化する（走査中に各要素のカタログ内インデックスを保持する）。
2. 各グループ内を **`(rarity.sortOrder, カタログ内インデックス)` の辞書順**で昇順に並べる。第 2 キーを入れるのは、Swift の `sort` が安定ソートを保証しないため。**同じカタログに対して常に同じ並びになることを構造的に保証する**。
3. `ownedItemIDs.contains(item.id)` で入手済みを判定し、`CollectionCellContent.make` を通す。
4. グループを `BodyPart.sortOrder` 昇順に並べ、`cells` が空のグループを除外して返す。

**防御的処理**（`ownedItemIDs` を「信頼しない入力」として扱う）

| 条件 | 扱い |
|---|---|
| `ownedItemIDs` にカタログに無い ID が含まれる | 無視する（判定は `contains` の片方向のみで、集合側を走査しない） |
| `ownedItemIDs` が空 | 全 26 件が未入手表示になる（正しい初期状態に縮退する） |
| `ownedItemIDs` がカタログの全 ID を含む | 全 26 件が入手済み表示になる |

**計算量**: 26 件の走査 1 回 + 部位ごとのソート（最大 5 件）。カタログが 100 件に増えても同じ実装で問題にならない。

### 5. 画面仕様

#### 5.1 タブ構成（`RootTabView` の変更）

practice-record が導入した 2 タブに、図鑑を 1 つ足して L1 の 3 画面を満たす。

| 順 | タブ | 内容 | SF Symbols |
|---|---|---|---|
| 1 | ガチャ | `GachaView`（既定の選択タブ） | `sparkles` |
| 2 | 図鑑 | `CollectionView`（**本機能で新規**） | `square.grid.2x2` |
| 3 | 履歴 | `HistoryView` | `list.bullet` |

- 変更は `RootTabView.swift` に `Tab` を 1 つ挿入するだけ。ラベルは「図鑑」の 2 文字 + SF Symbols で、**アセットは追加しない**。
- 起動時の選択タブはガチャのまま。タブ選択状態を永続化しない。したがって gacha-draw / practice-record の受け入れ条件「起動直後に表示されるのがガチャ画面」は維持される。
- タブバー高さ 49pt は practice-record 導入時から変わらない。**ガチャ画面・履歴画面のレイアウト予算（598pt）に影響を与えない**。
- 図鑑タブの中身は初回選択時に構築される。起動経路（T1）にセクション構築が入らない。

#### 5.2 図鑑画面（`CollectionView`）

上から下まで **画面全体が 1 つのスクロール領域**。固定ヘッダを持たない（コンプ率表示が MVP 対象外のため、常時可視にすべき要素が存在しない）。

```
ScrollView
 └ LazyVGrid(columns: 3 固定, spacing: 12)
     ├ Section("首")      → セル ×5
     ├ Section("肩")      → セル ×5
     ├ Section("腰")      → セル ×5
     ├ Section("背中")    → セル ×4
     ├ Section("脚")      → セル ×3
     ├ Section("目・手首") → セル ×2
     └ Section("ご褒美")  → セル ×2
```

- 列数は **3 列固定**（`GridItem(.flexible())` × 3）。端末幅による可変列数にしない（設計基準機で成立すれば、より広い端末ではセルが広がるだけ）。
- スクロール位置を永続化しない。タブを開くたび先頭から表示する。
- 空状態を持たない。カタログは常に 20 件以上あるため、記録が 0 件でも「全件シルエットのグリッド」が正しい初期状態であり、それ自体が「これから埋める対象」の提示になる。

**レイアウトメトリクス（設計基準: iPhone SE 第 2/3 世代 375×667・縦画面固定）**

横方向の検算（画面幅 375pt）:

| 区間 | 幅 |
|---|---|
| 画面左余白 | 16 |
| セル | 107 |
| 列間 | 11 |
| セル | 107 |
| 列間 | 11 |
| セル | 107 |
| 画面右余白 | 16 |
| 合計 | **375** |

検算: 16 + 107 + 11 + 107 + 11 + 107 + 16 = **375** ✓

セル内の縦配分（既定文字サイズ）:

| 要素 | 高さ |
|---|---|
| セル上パディング | 8 |
| レア度バッジ（`.caption` bold） | 18 |
| 余白 | 4 |
| 絵文字（40pt フォント固定） | 48 |
| 余白 | 4 |
| 種目名（13pt × 最大 2 行、行高 16） | 32 |
| セル下パディング | 8 |
| 合計 | **122** |

検算: 8 + 18 + 4 + 48 + 4 + 32 + 8 = **122** ✓

グリッド全体の高さ（既定文字サイズ・初回同梱 26 件）:

| 内訳 | 計算 | 高さ |
|---|---|---|
| 画面上余白 | 16 | 16 |
| セクション見出し × 7 | 28 × 7 | 196 |
| セル行 × 11 | 122 × 11 | 1342 |
| セクション内の行間 × 4 | 12 × 4 | 48 |
| セクション間余白 × 6 | 16 × 6 | 96 |
| 画面下余白 | 16 | 16 |
| 合計 | | **1714** |

検算: 16 + 196 + 1342 + 48 + 96 + 16 = **1714** ✓
行数の内訳: 首 2 + 肩 2 + 腰 2 + 背中 2 + 脚 1 + 目・手首 1 + ご褒美 1 = **11 行** ✓（3 列なので 5 件 → 2 行、4 件 → 2 行、3 件以下 → 1 行）

利用可能高さ = セーフエリア 647 − タブバー 49 = **598pt**。全体で 1714pt なので約 2.9 画面分となり、スクロール前提の画面である。初期表示（スクロールなし）では **上端から 466pt** の位置まで（＝「首」5 件と「肩」の 1 行目 3 件の合計 8 セル）が視界に入る。

検算: 16（上余白）+ 28（首見出し）+ 122 + 12 + 122 = 300（首 2 行目の下端）→ + 16 + 28（肩見出し）= 344 → + 122 = **466** ≤ 598 ✓
肩の 2 行目の下端は 466 + 12 + 122 = 600 > 598 のため、初期表示では収まらずスクロールで到達する。

**Dynamic Type**: セルの高さは固定せず内容に追従させる（`LazyVGrid` の行高は行内で最も高いセルに合わせて伸びる）。上表の 122pt は既定文字サイズでの設計値であり、上限は設けない。

| 要素 | フォント | 追随 |
|---|---|---|
| セクション見出し | `.headline`（17pt） | 上限なし（AX5 まで） |
| レア度バッジ | `.caption` bold（13pt） | 上限なし |
| 種目名 / 「???」/「未入手」 | `.caption`（13pt）、最大 2 行、`.minimumScaleFactor(0.85)` | 上限なし |
| 絵文字 | `.system(size: 40)` 固定 | **追随しない**（装飾要素。シルエットの大きさを一定に保つ） |

画面全体がスクロール領域のため、文字が伸びてもクリップされず、行が縦に伸びるだけで全件へ到達できる。

#### 5.3 詳細シート（`CollectionDetailSheet`・q4 回答）

入手済みセルのタップで `.sheet(item:)` を提示する。**未入手セルではシートを開かない**（§3）。

- 中身は `StretchCardView(item: item, style: .detail) { Button("閉じる") { ... } }`。図鑑専用のカード表示を作らず、フッタースロットに「閉じる」を差し込むだけ。
- `presentationDetents` は `[.large]` を明示する（中間ディテントでの手順の見切れを作らない）。
- 「はじめる」ボタンを置かない（図鑑は閲覧のみ。stretch-timer 側の既存決定を維持）。
- グラバー（`presentationDragIndicator(.visible)`）を出す。下スワイプでも「閉じる」でも同じ経路で閉じられる。
- シートは常時アクセスできる画面ではなく、1 タップで開いて 1 タップで閉じるモーダルであるため、L1 の「画面は 3 つまで」に加算しない（stretch-timer の `fullScreenCover` と同じ整理）。

**シート内の縦配分（設計基準機・`.large`。シート上端が画面上端から 44pt 下がる前提）**

利用可能高さ = 667 − 44 = **623pt**

| 区間 | 高さ |
|---|---|
| グラバー領域 | 20 |
| カード（`.detail`） | 最大 515 |
| カード〜フッター間 | 16 |
| フッターボタン「閉じる」 | 56 |
| シート下余白 | 16 |
| 合計 | **623** |

検算: 20 + 515 + 16 + 56 + 16 = **623** ✓

カード内の固定部は stretch-card §4.3 の `.detail` メトリクスのまま（種目名 2 行で 239pt、1 行で 213pt）なので、

- 手順スクロール領域 = 515 − 239 = **276pt**（種目名 2 行時）／ 515 − 213 = **302pt**（1 行時）

| 手順のケース | 高さ（`24nk + 10(n−1)`） | 276pt に対して |
|---|---|---|
| 4 手順 × 1 行（同梱データの典型） | 126 | 収まる |
| 6 手順 × 1 行 | 194 | 収まる |
| 4 手順 × 2 行 | 222 | 収まる |
| 5 手順 × 2 行 | 280 | スクロール |
| 6 手順 × 4 行（カタログ規約の最大） | 626 | スクロール |

stretch-card の受け入れ条件（レア度バッジ・部位チップ・種目名・実施時間・フッターが常時可視／手順のみスクロール／規約最大でも全文へ到達可能）は 276pt でも引き続き満たされる。**`Card/` 配下は 1 ファイルも変更しない。**

#### 5.4 更新のタイミング

図鑑は入手集合のスナップショットから組み立てた `[CollectionSection]` を `@State` に持つ。永続化層の観測挙動に依存せず、明示的な契機で再構築する。

| 契機 | 処理 |
|---|---|
| `onAppear`（タブ選択のたびに発火） | `rebuild()` |
| `scenePhase` が `.active` に戻る | `rebuild()` |
| 詳細シートを閉じたとき | 何もしない（閲覧のみで入手状態は変わらない） |

```swift
private func rebuild() {
    sections = CollectionSectionBuilder.build(items: catalog.allItems,
                                              ownedItemIDs: store.ownedItemIDs())
}
```

`ownedItemIDs()` は practice-record のメモリ索引を返すため **fetch 0 本**。`build` は O(26) の同期処理で、実機設計目標 1ms 未満。タイマー完了 → ガチャタブ → 図鑑タブと切り替える実利用の経路で、必ず `onAppear` を通って最新の入手状態が反映される。

#### 5.5 アクセシビリティ（VoiceOver）

- セルは `.accessibilityElement(children: .ignore)` で 1 要素にまとめ、`.accessibilityAddTraits(.isButton)` を付ける。
  - 入手済み: ラベル「首の横倒し、レア度 N、入手済み」、ヒント「詳細を開く」
  - 未入手: ラベル「未入手、レア度 N」、ヒントなし。**視覚上「???」と「未入手」のどちらが出ていても読み上げは変わらない**
- 絵文字・シルエットは装飾のため `.accessibilityHidden(true)`。「???」の文字列を読み上げさせない（ラベルを上書きしているため構造的に発生しない）。
- セクション見出しは標準の `Section` ヘッダとしてそのまま読まれ、部位名が読み上げられる。
- 詳細シート内の読み上げは stretch-card §4.7 の規則をそのまま使う（本機能で追加・変更しない）。「閉じる」は標準の `Button` でラベルがそのまま読まれる。
- セルの最小タップ領域は 107 × 122pt で、44 × 44pt を満たす。

### 6. データモデル（永続化）

**なし。** 本機能は SwiftData のモデルを 1 つも定義せず、`ModelContext` を参照せず、**`SwiftData` を import しない**。

- 表示状態（`sections` / `selectedItem` / `revealedUnownedID`）はビューのメモリ上にのみ存在し、タブを離れれば消えてよい。
- 入手済み判定の唯一の正は practice-record の `PracticeRecord`。図鑑は読むだけで、記録を作らない・更新しない・削除しない。
- 既読フラグ（NEW バッジ用）を持たない（q3 回答）。永続化する状態が 1 つも増えない。

### 7. 処理フロー

```
[起動]  RootTabView（既定選択 = ガチャ）
   └─ 図鑑タブの中身はまだ構築されない（T1 に 0 秒を追加）
   ▼
[図鑑タブを選択] CollectionView.onAppear
   ├─ store.ownedItemIDs()                       ← メモリ索引。fetch 0 本
   ├─ CollectionSectionBuilder.build(items:ownedItemIDs:)
   │      ├─ 部位でグループ化（カタログ記載順を保持）
   │      ├─ (rarity.sortOrder, カタログ内インデックス) で昇順ソート
   │      ├─ CollectionCellContent.make(from:isOwned:)   ← 未入手は name を載せない
   │      └─ BodyPart.sortOrder 昇順・空セクション除外
   └─ sections に代入 → LazyVGrid が描画（I/O なし・非同期なし）
   ▼
[入手済みセルをタップ]
   └─ selectedItem = item  →  .sheet で CollectionDetailSheet 提示
         └─ StretchCardView(item:style:.detail) + 「閉じる」
               └─ 閉じる → selectedItem = nil（入手状態は変わらない）
   ▼
[未入手セルをタップ]
   └─ revealedUnownedID をトグル（同じ id なら nil、別 id ならその id）
         └─ 当該セルの種目名だけが「???」→「未入手」に差し替わる（他セルは元に戻る）

--- 入手の反映経路 ---
[ガチャタブ → 実施 → タイマー完了]
   └─ practice-record が索引を更新（本機能は関与しない）
        ▼
[図鑑タブへ切り替え] onAppear → rebuild() → 当該種目が入手済み表示になる
```

**図鑑の描画経路に I/O・非同期・アニメーションを 1 つも置かない**ことを設計上の固定点とする。

## 非機能優先順位との対応

### 1 位: 学習容易性（説明書なしで初回起動 60 秒以内に最初のガチャ → 実施開始）

- **60 秒の予算に 0 秒を追加する**: 初回の導線（注意書き → ガチャ → カード → はじめる）に図鑑は一切登場しない。既定の選択タブはガチャのままで、起動直後に図鑑が出ることがない。stretch-timer §「1 位」の内訳 37.8 秒は変わらない。
- **操作対象を最小に保つ**: 図鑑画面の操作は「セルをタップする」「スクロールする」の 2 つだけ。整理軸の切り替えセグメント（q2 で不採用）、検索、フィルタ、並べ替えを置かない。覚えることが増えない。
- **画面の意味を 1 目で伝える**: 未入手をシルエット + 「???」で見せることで、「埋まっていない枠がある」ことが説明なしに伝わる。凡例・チュートリアル・「未入手とは」の説明文を置かない。
- **数字を出さない**: コンプ率・達成率・件数（3/5 等）を表示しない。読み解きの必要な表示を増やさず、埋まり具合はセルの見た目だけで伝える（L1 が「MVP はシルエット表示のみで進捗を示す」と定めた方針に一致）。
- **タップに必ず反応する**: 未入手セルも「未入手」と応答する（q1 回答 (2)）。無反応のセルを作らないことで「壊れている」と誤解させない。反応にダイアログもトーストも使わず、セル内で完結させる。
- **失敗状態を作らない**: エラーダイアログ・リトライ導線・「データがありません」プレースホルダを持たない。記録 0 件は「全件シルエット」という正常状態であり、それ自体が次に何をすべきかを示している。
- **色に頼らない**: レア度はバッジの文字（N/R/SR/UR）を必ず併記する。入手済み / 未入手の区別も、絵文字の階調・文字（「???」）・背景の 3 つで冗長に示す。

### 2 位: パフォーマンス（コールドスタート → 結果 3 秒以内、演出 60fps）

- **起動経路に一切入らない**: 図鑑タブの中身は初回選択時に構築される。T1（1.19 秒以下）と E2E（3.0 秒以内）に増分 0 で、practice-record が確保した 140ms の余裕をそのまま残す。
- **描画経路から I/O と非同期を排除する**: `SwiftData` / `URLSession` / `Task` / `async` を `Collection/` に持ち込まない。入手済み集合はメモリ索引から同期で取得し、fetch 0 本を維持する。
- **抽選・タイマーの経路に触れない**: 図鑑は `Gacha/` / `Timer/` を import しない。ガチャ演出中・カウントダウン中に図鑑側の処理が走る経路が構造的に存在しない。
- **重い描画機能を使わない**: `blur` / `shadow` / `mask` / `TimelineView` / `Canvas` を使わない。装飾は塗り・枠線・角丸のみ。画像アセットを持たないためデコードも発生しない。
- **階調変換を静的コンテンツに限定する**: シルエットの `.grayscale(1.0)` は未入手セルの絵文字にのみ適用し、アニメーションと併用しない。値が変化しないため再評価のたびに合成し直されない。
- **アニメーションを持たない**: グリッドの入場・セルの出現・シルエット解除・未入手ラベルの差し替えのいずれにも `.animation` / `withAnimation` を書かない。Reduce Motion への個別対応も不要になる。
- **`LazyVGrid` の遅延生成に任せる**: 26 セルは全件描いても問題にならない規模だが、標準 API の既定挙動を素直に使い、独自の可視判定・プリフェッチを実装しない。

### 3 位: 保守性（週末開発でも壊さず拡張できる）

- **表示ロジックを純粋関数に隔離する**: `CollectionSectionBuilder.build` / `CollectionCellContent.make` は SwiftUI・SwiftData・`Date`・乱数に依存せず、カタログの値型と `Set<String>` だけを受ける。並び順・伏せ方・防御的処理の検証が永続化層も UI テスト基盤もなしのユニットテストで完結する。
- **並び順を決定的にする**: 同一レア度内の第 2 キーにカタログ内インデックスを使い、安定ソートに依存しない。実装を少し変えても並びが揺れない。
- **他機能のコードをほぼ触らない**: 変更は `RootTabView.swift` へのタブ 1 つ挿入のみ。`Gacha/` / `Timer/` / `Card/` / `Record/` は 0 ファイル変更。practice-record が「`RootTabView` に 1 タブ足すだけで済む形にする」と設計した通りに載せる。
- **表現の定義を再定義しない**: レア度色は `RarityStyle`、部位名・レア度名は `displayName`、カード詳細は `StretchCardView(.detail)` を参照する。`Collection/` に色定数・部位名リテラル・カード用レイアウトを持たない。
- **種目追加でコードを触らせない**: 件数・部位別内訳・レア度別内訳をコードに焼き込まない。種目を 1 件追加してもセクションとセルが自動的に増えることをテストで実証する。
- **数値を 1 箇所に集約する**: 列数・余白・セル寸法・シルエットの階調と不透明度を `CollectionMetrics` にまとめ、ビューにマジックナンバーを書かない。
- **collection-progress の追加口を用意する**: コンプ率の算出に必要な値（`ownedItemIDs` とカタログの `totalCount`、セクションごとの `cells`）はすでに揃っている。同機能はグリッドの上にヘッダを 1 つ足すだけで載り、本機能の純粋関数・派生モデルの変更を伴わない。
- **テストは範囲・上限でアサートする**: 性能は「10,000 回 2 秒以内」という余裕を持った上限で書く。セル総数は「`catalog.totalCount` と一致」、セクション数は「1 件以上ある部位の数と一致」というデータ非依存の不変条件で書き、「26 件」「7 セクション」のような厳密値をテストに焼き込まない（種目を足すたびにテストが落ちると「追記だけで完結」が崩れるため）。一方、並び順・「???」の文字列・伏せ方のように経路差で揺れない値は厳密にアサートする。

### 妥協特性で簡略化すること

| 妥協特性 | 本機能で作らないもの |
|---|---|
| スケーラビリティ | 毎回カタログ全件を走査して素朴に組み立てる。`build` 結果のキャッシュ、差分更新、入手済み件数の集計テーブル、セルの仮想化チューニング、画像のプリフェッチを持たない。26 件（将来 100 件でも）で最適化する対象がそもそも存在しない |
| 互換性・相互運用性 | 図鑑の状態をエクスポート / インポートしない。共有画像の生成、スクリーンショット向けレイアウト、iPad・横画面・ウィジェット向けの派生レイアウトを作らない。多言語化せず日本語直書き |
| 運用性 | 描画時間の計測基盤、レイアウト崩れの検知、スナップショットテストの自動化、アナリティクス、`print` / `os_log` によるログを持たない。表示崩れは自分が使って気づいたら直す |

## セキュリティ

本機能は完全ローカル・読み取り専用の表示画面で、ネットワーク・永続化・テキスト入力のいずれも扱わない。攻撃面は「入手済み集合と `StretchItem` をどう描画するか」に限定される。

### 認証・認可

- **不要（実装しない）**。アカウント・ログインを持たない単一端末・単一ユーザー構成（L1 のスコープ外事項）。図鑑に権限による出し分けは存在しない。
- **書き換え経路を作らない**: `CollectionView` は `PracticeStore` の **読み取り API（`ownedItemIDs()`）のみ**を呼び、`record` / `loadIndex` / `refreshForCurrentDay` を呼ばない。図鑑から実施記録を作る・消す経路が存在しない。
- カタログを書き換える経路を作らない。`StretchItem` は `let` で受け取り、保持も改変もしない。

### 入力検証

- ユーザー入力はセルのタップ・スクロール・タブ切り替え・シートの開閉のみ。テキスト入力・数値入力・URL スキーム / ユニバーサルリンクの受け口を持たない。
- **入手済み集合を「信頼しない入力」として扱う**: 判定は `ownedItemIDs.contains(item.id)` の片方向のみで行い、集合側を走査しない。カタログに存在しない ID が混入していてもクラッシュせず、単に無視される（図鑑の分母はあくまでカタログ）。
- **`StretchItem` を「信頼しない入力」として扱う**: 絵文字は先頭 1 文字に切り詰め、空でもレイアウトが崩れないようにする。空の種目名でも例外にしない。カタログのバリデータが弾く値だが、図鑑単体でもクラッシュ・レイアウト破綻を起こさない。
- **未入手の情報が構造的に漏れない**: 未入手セルの派生モデルに `name` / `steps` / `durationSeconds` を載せない（§4）。ビューの条件分岐を書き間違えても実名が描画されない。加えて、未入手セルからはシートを開かない（`selectedItem` に代入する経路が入手済み分岐にしかない）。
- **テキストを書式として解釈させない**: セル・シート内の文字列はすべて `Text(verbatim:)` で描画する。`LocalizedStringKey` を受ける `Text` イニシャライザを `Collection/` で使わない（stretch-card / practice-record と同じ方針）。
- テキスト選択（`textSelection`）・データ検出・リンク化を有効にしない。図鑑からテキストが持ち出される経路を作らない。

### データ保護

- **何も保存しない**: SwiftData・UserDefaults・ファイル・キーチェーンのいずれにも書き込まない。既読フラグ（NEW バッジ用）を持たないため、永続化する状態が 1 つも増えない。
- 個人情報・端末識別子・位置情報・利用統計を扱わない。App Privacy「データ収集なし」申告（appstore-release-prep）と矛盾しない状態を維持する。
- **ネットワークを使わない**: `URLSession` / `Network` / `CFNetwork` を import しない。App Transport Security 設定を緩めない。
- **ログ出力を残さない**: `Collection/` 配下に `print` / `os_log` / `debugPrint` を書かない。入手状況を外部へ送らない。
- 図鑑の入手状況は健康関連の生活パターンを間接的に示し得るが、端末外へ出る経路（共有・エクスポート・同期・通知）を 1 つも作らないことで保護する。スクリーンショット制限は設けない（本人の端末で本人のみが見るため）。

### 依存関係

- 外部ライブラリ 0。`SwiftUI` / `Foundation` で完結する（L1 制約: 外部ライブラリ原則ゼロ）。`UIKit` も使わない（配色は `RarityStyle` / `AdaptiveColor` に委譲し、ハプティクスを持たない）。

### コンテンツ安全性（法務制約の技術的担保）

- 図鑑画面に追加する固定の日本語文言は「図鑑」「???」「未入手」「閉じる」の 4 つのみ。医学的効能・専門家監修・健康状態の評価を示唆する文言を書かない。
- 収集状況の解釈（「よく埋まっています」「不足しています」等の評価コメント）を一切表示しない。
- 種目名・手順・注意はすべて `StretchItem` 由来で、表示は stretch-card に委譲する。禁止語チェックは stretch-catalog のバリデータが担い、本機能で再実装しない（検査点を 2 箇所に分散させない）。
- 全体向けの注意書きは safety-notice の責務であり、図鑑画面に重複して置かない。

| 1 | 期限・マイルストーン「MVP を 2 週間で実機投入」 | NEW バッジと既読フラグの永続化を持たないと決めた判断（q3）。整理軸の切り替えセグメント、検索・フィルタ・並べ替え、部位ジャンプ導線、入手時の解放演出、図鑑からのタイマー起動を作らない判断 | 期間が延びる場合、まず NEW バッジ（既読状態の永続化 1 モデル追加）と入手時の解放演出を検討する余地がある。いずれも `Collection/` 内で完結し、`CollectionSectionBuilder` の並び順ロジックと `StretchItem` のスキーマには波及しない。ただし NEW バッジは「初回に図鑑を開いた時点」の定義と既読の書き込み経路が必要になり、本機能が現在「読み取り専用」であるという性質が変わる |
| 2 | 期限・マイルストーン「MVP を 2 週間で実機投入」 | 非機能要件の「実装完了時期: MVP（2 週間）内」 | MVP 期間が変わっても本機能の設計値（3 列固定・セル 107×122pt・グリッド全体 1714pt・シートの手順領域 276pt・fetch 0 本）は変わらない |
| 3 | 期限・マイルストーン「4 週間の自己利用で継続できたら App Store 公開を判断」 | コンプ率を表示せず、収集動機の効き具合を数値で追う手段を持たないと決めた判断（L1 が「MVP はシルエット表示のみで進捗を示す」と定めた方針に従う） | 4 週間の自己利用で「図鑑が埋めたくなる動機として機能しているか」を数値で確認したくなった時点で collection-progress に着手する。必要な値（`ownedItemIDs` と `totalCount`、セクションごとの `cells`）はすでに揃っており、グリッドの上にヘッダを 1 つ足すだけで載る。本機能の純粋関数・派生モデル・セルの表現には波及しない |
| 4 | 配布・審査「当面は Xcode 直接インストール。4 週間後に App Store 公開を判断」 | ストア掲載スクリーンショット向けの見栄え調整（グリッドの装飾、レア度別の背景演出、コンプ状態の見せ方の作り込み）を本機能では行わないと決めた判断。および多言語化しない判断 | 公開判断が前倒しになった場合、掲載物の見栄え調整は appstore-release-prep 側で行う。図鑑は「埋まっている画面」がスクリーンショット映えする画面になり得るが、その調整は `CollectionMetrics` と `CollectionCellView` の変更で収まり、純粋関数群には波及しない。多言語化は App Store 公開に必須ではないため、この判断は覆らない見込み |
